# 데카르트 QA: EmailToMCP 자동 업데이트 P1 최소기능(확인+알림+링크) 기능검증

## 1. 결론: 조건부 Go

- **기능 단위(확인+알림+링크) 판정은 Go입니다.** §14.6 매트릭스 20개 케이스가 모두 테스트로 구현돼 있고 통과했습니다. §11.8 상태 6가지와 설정 > 업데이트 탭도 동작합니다.
- **§12.3 P1 완료기준 중 업데이트 항목은 아직 "통과"로 볼 수 없습니다.** 아래 조건 C1~C4가 남아 있습니다. 그중 C1(운영 키)이 해결되지 않으면 v1.0.0 출시는 No-Go입니다.

직접 확인한 결과는 다음과 같습니다. 전체 스위트는 돌리지 않았고 지정된 파일만 실행했습니다.
- 업데이트 테스트 6개 파일: `.venv` Python으로 **150 passed (11.4초)**. Edison이 보고한 182개는 다른 파일까지 합친 수치로 보입니다. 시스템 Python으로 돌리면 `markdown` 모듈이 없어 수집 단계에서 오류가 나므로 반드시 `.venv`를 써야 합니다.
- ruff: 업데이트 관련 소스, app, main_window, settings_dialog, 테스트 전부 통과했습니다.
- mypy: `update/`와 `update_banner.py`(9개 파일) 이슈 0건입니다.
- 커버리지는 **측정하지 못했습니다.** `.venv`에 `coverage`와 `pytest-cov`가 설치돼 있지 않습니다.

## 3. §11.8 상태 표와 설정 탭

| 상태 | 구현 | 테스트 |
|---|---|---|
| 최신 | 배너 없음, 설정에 "최신 버전입니다." | 있음 |
| 새 버전 | 비모달 배너와 상태줄 배지, [나중에]는 해당 버전에만 적용 | 있음 |
| 보안 업데이트 | 주황 강조 배너, 닫으면 24시간 뒤 다시 표시 | 있음 |
| floor 미달 | 고정 빨간 배너, [나중에] 없음 | 있음 |
| 확인 불가 | 설정에 사유 표시, 7일 지나면 배너 | 있음 |
| 보안 경보 | 비모달 경보 다이얼로그, 배지, 자동확인 정지 | 로직/배지는 있음. 다이얼로그를 띄우는 UI 테스트는 없음(경미) |

설정 > 업데이트 탭: 현재 버전(dev 빌드 표시 포함), 채널, 자동확인 체크박스, 마지막 확인 시각, 결과 문구, [지금 확인](비동기, 진행 중 비활성). `test_settings_update_tab_shows_status_and_checks_now`가 검증.

자동확인 on/off는 [저장]을 눌러야 반영되고 저장 실패는 조용히 무시됨 — 기존 설정 탭 패턴과 같아 결함으로 보지 않음.

## 4. "지시와 다르게 한 부분" 평가

**(핵심) 운영 공개키를 비우고 fail-closed로 처리한 것은 타당합니다.**
- 저장소가 공개이고 테스트 비밀키도 `tests/fixtures`에 공개돼 있습니다. 테스트 공개키를 운영 빌드에 내장하면 누구나 매니페스트를 위조할 수 있는 뒷문이 됩니다. Edison의 판단이 옳고, `test_test_keys_are_never_embedded_in_production`이 회귀를 방지합니다.
- "기능이 있기는 하다"고 볼 수 있습니다. 검증·판정·배너·링크의 전체 경로는 DI로 주입한 키로 끝까지 검증됐고, 실제 조립 상태(`_build_update_checker`)는 네트워크 요청 없이 "확인 불가(서명 검증 키 미내장)"로 닫힙니다.
- 다만 **이 상태로 출하하면 모든 사용자에게 업데이트 알림이 절대 오지 않습니다.** §14.6 매트릭스는 테스트 기준 충족이지만, P1 출시 게이트(v1.0.0) 기준으로는 **키 내장(D-8) 전까지 미충족**입니다(조건 C1).

나머지 8가지:

| # | 내용 | 평가 |
|---|---|---|
| 1 | base_url을 CLI 옵션 대신 환경변수(`EMAILTOMCP_UPDATE_BASE_URL`)로 받음 | 합리적. dev 빌드에서만 받고 정식 빌드는 무시함을 테스트로 확인 |
| 2 | 주기작업을 범용 `schedule_periodic`으로 구현 | 합리적. 1시간 tick마다 벽시계 24시간 경과 판단, 절전 복귀에도 강함. 종료 시 취소 처리됨 |
| 3 | 보안경보 후에도 수동확인은 허용 | 합리적. 자동확인은 정지(네트워크 요청 0건 확인), 수동확인 성공 시 해제 |
| 4 | 서명 실패/해시 충돌만 경보로 처리 | 설계(§11.8)와 정확히 일치. 롤백/미래시각/서명파일없음은 "확인 불가" |
| 5 | floor 배너 문구 변경 | 합리적(P1엔 자동발송/MCP발송이 없어 "정지" 문구가 사실과 다름). 단 **DESIGN.md §11.8 문구 미갱신**(C4) |
| 6 | dev 빌드 수동확인 시 판정만 표시 | §14.4와 일치 |
| 7 | 설정키 변경 | 문제없음. 설계서 미반영만 C4에 포함 |
| 8 | httpx2 사용 | 접근은 합리적이나 **`pyproject.toml`에 httpx/httpx2 둘 다 미선언**. 클린 환경에서는 업데이트 확인이 조용히 실패함(C2) |

## 5. 매뉴얼 동기화 (CLAUDE.md §1)

- `00_인덱스.md`는 U2 제외 범위를 명시. `01_메인창.md`의 배너 4종/버튼/배지, `07_설정.md`의 업데이트 탭/필수업데이트/보안경보/7일 미확인 설명은 실제 화면과 구조상 일치.
- 다만 "이 빌드에는 업데이트 서명 검증 키가 내장되지 않아 확인할 수 없습니다"라는, 키 미내장 상태에서 항상 보이는 사유가 07의 "확인 불가" 설명에 없음(경미, C4에 포함).
