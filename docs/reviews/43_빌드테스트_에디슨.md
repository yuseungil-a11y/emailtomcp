# PyInstaller 빌드 테스트 — Edison

## 빌드결과: 성공
nohup+disown 방식, 약2분(캐시영향), 산출물 `dist/emailtomcp/emailtomcp.exe`(11.75MB, 전체167MB).

## 사전점검
.venv에 PyInstaller 6.22.3 기설치. spec 최신상태(re2/psutil hiddenimports 반영됨, 실제venv에 google-re2/psutil/mcp/httpx2/uvicorn 전부설치확인).

## 스모크테스트
- `--version`: 정상, "emailtomcp 1.0.0.dev0+unknown"(git태그없어fallback값, 블로커아님)
- **`--help`: 크래시(버그)**: `UnicodeEncodeError: 'cp949' codec can't encode character '—'`. `__main__.py:20` argparse description에 em dash(—, U+2014)가 들어있는데 한국어Windows콘솔기본코드페이지(cp949)로 인코딩불가 — exit 1. GUI전용실행(console=False)엔 영향없으나 콘솔 --help나 CI스모크서터짐.
- GUI모드(--mcp-port 0, 격리데이터디렉터리): 정상기동, 크래시없음. DB마이그레이션완료(user_version=4), 자동회신컨트롤러기동(enabled=False), MCP서버기동(임의포트정상할당), 10초이상생존확인후정리.

## 빌드로그 경고(무해)
tzdata 미발견(zoneinfo직접사용없음, 낮은위험), pycparser lextab/yacctab(런타임재생성, 무해), 그외missing module(Windows빌드서미사용되는선택적임포트, 정상범주).

## 미조치
em dash 버그는 스펙/빌드범위밖소스수정이라 보고만(제우스가직접수정예정). git커밋/push 안함.

## 관련파일
`dist/emailtomcp/emailtomcp.exe`, `build.log`, `packaging/emailtomcp.spec`, 버그위치 `src/emailtomcp/__main__.py:20`
