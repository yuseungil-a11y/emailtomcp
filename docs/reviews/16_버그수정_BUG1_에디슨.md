# BUG-① (인코딩 안 된 UTF-8/EUC-KR 헤더 메일 파싱 크래시) 수정 — Edison

## 요약
`mail/mime/parse.py`와 그 테스트만 수정(다른 서브에이전트 작업 파일 미접촉). 33건 테스트 통과(신규 2건 포함), ruff/mypy 클린.

## 원인
`email.message_from_bytes()`는 RFC 2047 인코딩 없이 비ASCII 바이트가 그대로 담긴 헤더(From/Subject 등)를 str이 아니라 `email.header.Header` 객체로 반환. `_unfold(value)`(parse.py:84)가 value를 항상 str로 가정하고 정규식(`_FOLD_RE.sub`)에 바로 넘겨 TypeError 발생 → `parse_eml`의 `except Exception`에 걸려 `parse_limited=True`로 강등, From/Subject/body/Message-ID 전부 소실.

## 수정 내용 (`src/emailtomcp/mail/mime/parse.py`)
1. `_unfold`: str이 아닌 값(Header)이 들어오면 정규식 전에 `_decode_header_text`와 같은 경로(email.header.decode_header)로 먼저 디코딩. decode_header가 Header의 내부 `_chunks`를 `(bytes, 'unknown-8bit')` 형태로 꺼내주고, 기존 `decode_bytes`(charset_normalizer 추정 폴백 포함)가 처리 — 추가 모듈 변경 없이 안전 디코딩.
2. `_decode_header_text`: 타입힌트를 `str | email.header.Header | None`으로 보강, decode_header 자체가 예외를 던지는 극단적 폴백 분기에서도 항상 str 반환하도록 수정(`str(value)`) — 안 그러면 `_unfold`에서 2차 TypeError 날 여지.
3. `_parse_address_list`/`_first_msgid`/`_split_msgids`/`_parse_date`/`_parse_priority` 타입힌트도 Header 가능성 반영(동작변경 없음, 명확성 목적).
4. `_unfold` 호출경로(From/To/Cc/Bcc/Reply-To/Message-ID/In-Reply-To/References/Date/X-Priority/Importance) 전부 점검. Subject는 원래 `_unfold`를 거치지 않고 `_decode_header_text`를 직접 써서 이미 안전(재확인, 코드 그대로 둠). Content-Type/Content-Disposition은 RFC상 ASCII 토큰이라 범위 밖으로 판단, 미수정.

## 테스트 추가
- `tests/fixtures/eml/generate_fixtures.py`: `gen_raw8bit_utf8_header()`, `gen_raw8bit_euckr_header()` 추가 → `raw8bit_utf8_header.eml`, `raw8bit_euckr_header.eml` 생성(기존 8종 바이트 동일, 재생성해도 무변화 확인).
  - EUC-KR 케이스는 charset_normalizer가 짧은 한글을 다른 CJK 인코딩으로 오판할 수 있어(기존 decode_bytes의 "추정 실패 시 best-effort" 특성, 범위 밖), fixture를 충분히 긴 한글 문구로 구성해 디코딩 정확도까지 확인되도록 설계.
- `tests/unit/test_mime_parse.py`: `test_raw8bit_utf8_header_not_limited`, `test_raw8bit_euckr_header_not_limited` 추가(parse_limited=False, From이름/주소·Subject·Message-ID·body_text 전부 정상추출 검증) + `test_never_raises` 파라미터 목록에 두 fixture 추가.

## 실행 결과
`test_mime_parse.py`+`test_mime_build.py`+`test_mime_limits.py` 지정실행(전체스위트 아님) → **33건 전부 통과(0.22초)**. 수정 전에는 신규 2건이 TypeError로 실패함을 재현 확인 후 수정 적용. ruff check/mypy 모두 parse.py 클린.
