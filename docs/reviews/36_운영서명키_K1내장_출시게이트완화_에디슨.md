# 운영 서명키(K1) 내장 및 출시게이트 완화 — Edison

## 배경
사용자가 minisign으로 Ed25519 키쌍을 직접 생성(비밀키는 본인 보관), 공개키만 전달받아 반영. 이후 "예비키(K2) 없이 K1 단일키로 운영"하기로 결정.

## 1. K1 공개키 내장 (`src/emailtomcp/update/keys.py`)
```python
EMBEDDED_PUBLIC_KEYS = (
    ("K1", "active", "RWRsNFPfSdZbIOJCGCtFny5oT+uyBqtw+zTK/B8Ufs/GFX/Fi2M2K5nC"),
)
```
형식: (라벨, 역할, minisign공개키base64) 튜플. `embedded_trusted_keys()`가 `parse_public_key()`로 파싱. 디코딩 확인: 42바이트, 접두Ed, key_id=`205BD649DF53346C`. 실제 파싱 성공 확인.

신규테스트(test_update_keys.py): K1이 key_id 1개로 정확히 조회되는지, 테스트키로 서명후 key_id만 K1으로 바꾸면 UnknownSigningKey아닌 SecurityError(서명불일치경보)로 나오는지(=K1이 실제 신뢰목록에서 조회됨 확인), 미등록 key_id는 UnknownSigningKey로 처리되는지.

기존 test_app_builds_checker_with_embedded_keys_fail_closed(test_update_checker.py)는 키가 비어있다는 전제라 K1 내장후 실패+실제 GitHub Pages로 네트워크요청까지 나감 — EMBEDDED_PUBLIC_KEYS=() monkeypatch로 수정해 "키없으면 닫힌상태" 동작 계속검증. 신규 test_app_builds_checker_with_production_keys_rejects_test_key 추가(앱 실제조립경로+가짜서버, 테스트키서명매니페스트는 경보없이 "확인불가"로거부 확인).

## 2. 출시게이트 완화(예비키 요구 제거)
`test_release_build_has_embedded_keys`에서 standby키 요구 단언 제거 — 이제 "active키1개이상"만 확인(`_assert_release_key_gate()`헬퍼로 분리). 개발빌드 skip설정은유지.
신규테스트: `test_release_key_gate_passes_with_single_active_key`(개발빌드서도항상실행, K1하나로게이트통과+예비키없음확인), `test_release_key_gate_fails_without_active_key`(키목록비어있거나예비키만있으면여전히실패).

**서명검증동작자체는불변**: fail-closed, 미지key_id거부, SecurityError/UnknownSigningKey구분, standby역할수용기능(KeyRole) 전부그대로. 테스트키가운영키목록에안섞이는검사도유지.

## 3. DESIGN.md 갱신
§14.7 상단에 "2026-10-05 사용자결정: 예비키(K2)없이 K1단일키로운영…" 안내. 1항(키생성)·3항(공개키배포) K1기준수정. 6~8항(회전·유출·분실대응)은 "예비키도입시만쓰는참고절차, 지금은미적용"표시(삭제안함). D-8행에 완화결정기록, 남은일 "백업보관장소확정"만. 변경이력(85행)에 짧은메모추가.
