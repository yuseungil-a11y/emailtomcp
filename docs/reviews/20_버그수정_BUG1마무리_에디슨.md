# BUG-① 마무리 수정 (D-1, D-2) — Edison

## 요약
D-1(크래시, 상)과 D-2(파일명 손상, 중) 모두 `mail/mime/parse.py`에서 수정 완료. 지정 테스트 37건 통과(이전 33+신규4). ruff/mypy 클린.

## D-1 수정 (크래시)
- `parse.py:285`: `disposition = (part.get("Content-Disposition") or "").lower()` → `_unfold(part.get("Content-Disposition") or "").lower()`
- `parse.py:296`: `content_id = content_id.strip().strip("<>")` → `content_id = _unfold(content_id).strip().strip("<>")`
- Header 객체(인코딩 안 된 8비트)가 들어와도 `_unfold`가 먼저 안전하게 str 변환해 AttributeError 제거.

## D-2 수정 (파일명 손상)
- 근본원인: `_attachment_filename`이 `part.get_filename()`에 의존하는데, 내부에서 `str(Header)` 변환 시 compat32가 surrogateescape로 들여온 8비트 바이트가 **복구불가능한 U+FFFD로 뭉개짐**(surrogateescape 재인코딩 복원 시도 → 실제론 replace 처리라 통하지 않음을 테스트로 확인 후 접근 변경).
- 신규 헬퍼 `_filename_param_from_raw_header()`: `part.get_filename()`을 거치지 않고 원본 Header 객체를 `_decode_header_text`로 먼저 안전 디코딩 → 그 문자열로 임시 `email.message.Message`를 만들어 표준 `get_param`(RFC2231 continuation 등) 재사용. Content-Disposition filename 우선, 없으면 Content-Type name(기존 get_filename() 우선순위와 동일). 헤더가 순수ASCII(str)인 기존 정상케이스는 이 경로를 안 타고 원래 로직 그대로 사용 — 회귀 없음.

## 테스트/fixture 추가
- `generate_fixtures.py`에 2종 추가(총 12종): `raw8bit_attachment_filename.eml`(Content-Disposition filename+Content-ID 둘다 8비트, D-1 재현), `raw8bit_contenttype_filename.eml`(Content-Type name만 8비트, D-2 재현).
- `test_mime_parse.py`에 `test_raw8bit_attachment_filename_not_limited`(parse_limited=False, 본문보존, filename_raw=="한글문서.pdf", content_id=="첨부식별자"), `test_raw8bit_contenttype_filename_decoded`(filename_raw=="첨부사진.jpg", 깨진문자열 아님) 추가 + test_never_raises 파라미터에 두 fixture 추가.
