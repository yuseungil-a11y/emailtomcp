# EmailToMCP 테스트 전략 (Galileo / test-writer, v0.1 설계 검토)

이 문서는 계획만 담고 있다. 테스트 코드는 아직 작성하지 않았다.

## 0. 테스트 가능성을 위한 설계 수정 제안 (DI 포인트)

| 이슈 | 현재 설계 | 문제 | 제안 |
|---|---|---|---|
| 시간 의존 로직 | 쿨다운 24h, 레이트리밋, 재시도 백오프, 승인 대기 120초 | 테스트를 돌리면 실제 시간만큼 기다려야 한다 | `Clock` 프로토콜(`now/monotonic/sleep`)을 주입받는다. 테스트에서는 `FakeClock.advance()`로 시간을 넘긴다 |
| 프로세스 실행 | `claude_runner`가 subprocess와 psutil을 직접 호출한다 | 테스트 결과가 들쭉날쭉해진다 | `ProcessRunner`(`spawn/wait/kill_tree`)를 주입받는다. 단위 테스트는 fake를 쓰고, 통합 테스트만 실제 `fake_claude.py`를 실행한다 |
| HTTP(업데이트) | 아직 설계에 없다 | base_url을 하드코딩하면 가짜 서버로 테스트할 수 없다 | `release_client`가 생성자에서 `base_url`과 `http_client`를 받는다 |
| 비밀 저장 | keyring을 직접 호출한다 | CI의 Keychain 프롬프트에서 테스트가 멈춘다 | `SecretStore` 프로토콜로 감싼다. 테스트에서는 autouse fixture로 인메모리 backend를 쓴다 |
| 단일 인스턴스와 포트 | QLockFile을 쓰고 포트가 8765로 고정이다 | 병렬 테스트끼리 충돌한다 | `EMAILTOMCP_DATA_DIR` 환경변수와 `--mcp-port 0` 옵션으로 덮어쓸 수 있게 한다 |
| Qt 경계 | — | backend가 PySide6를 import하면 단위 테스트에 QApplication이 필요해진다 | "backend/core/rules/mail/autoreply/mcp_server는 PySide6 import 금지" 규칙을 아키텍처 테스트로 강제한다 |
| cli_locator | 로그인 셸에서 `command -v`를 실행한다 | 느리고 결과가 들쭉날쭉하다 | `ShellProbe` 인터페이스로 감싼다 |
| 조기 종료 | `--version` 처리 시점이 정해지지 않았다 | PyInstaller 스모크 테스트의 전제가 된다 | `--version`과 `--help`는 Qt, DB, 네트워크를 초기화하기 전에 출력하고 종료한다 |

## 1. 테스트 피라미드와 구조

비율은 단위 70%, 통합 20%, UI/E2E 10%로 잡는다.

```
tests/
├─ conftest.py   (clock, tmp DB, fake secret store)
├─ unit/ core storage mail/{mime,incoming,outgoing} rules autoreply mcp_server update runtime
├─ integration/ mail_servers mcp autoreply update
├─ docker/       (GreenMail 교차검증)
├─ ui/           (pytest-qt offscreen)
├─ e2e_claude/   (실제 claude, 옵트인)
├─ fixtures/ eml/ releases/ certs/
└─ fakes/ fake_claude.py fake_claude_scenarios/ fake_pop3_server.py fake_imap_server.py fake_github_releases.py
```

```toml
[tool.pytest.ini_options]
markers = [
  "unit: 외부 I/O 없는 순수 로직",
  "integration: 로컬 I/O, docker 불필요(aiosmtpd, in-process FastMCP, fake_claude)",
  "docker: GreenMail 등 docker 필요, 미가용 시 자동 skip",
  "ui: pytest-qt, QT_QPA_PLATFORM=offscreen",
  "e2e_claude: 실제 claude CLI + 로그인 필요, 옵트인",
  "slow: 1초 이상",
]
addopts = '-m "not docker and not e2e_claude and not slow" --strict-markers'
```

docker 마커가 붙은 테스트는 `which docker`와 `docker info`로 사용 가능 여부를 확인한다. 쓸 수 없으면 실패가 아니라 skip으로 처리하고 사유를 남긴다.

## 2. 메일 서버 테스트

| 프로토콜 | 1차 | 2차 | 비고 |
|---|---|---|---|
| SMTP | aiosmtpd | — | 인증 실패, 지연, STARTTLS를 재현할 수 있다 |
| POP3 | 직접 만든 `fake_pop3_server.py`(asyncio. USER/PASS/STAT/LIST/UIDL/RETR/DELE/QUIT) | — | 표준 라이브러리에 POP3 서버가 없다 |
| IMAP | `fake_imap_server.py`(LOGIN/SELECT/UID FETCH/UID SEARCH/STORE/APPEND/LOGOUT) | GreenMail docker(P4: IDLE, UIDVALIDITY, 다중 폴더) | fake 서버로 P1~P3 회귀를 돌린다. GreenMail은 docker가 없는 Windows에서도 문제없도록 2선 검증으로만 쓴다 |
| TLS | `fixtures/certs/`(정상, 만료, 호스트명 불일치) | — | §8 인증서 검증을 확인한다 |

`IncomingProvider` contract test 하나를 `[pop3→fake]`, `[imap→fake]`, `[imap→GreenMail]` 세 조합에 parametrize로 적용한다.

## 3. MCP 서버 테스트

in-process로 `httpx.ASGITransport`와 공식 SDK `streamable_http_client`를 연결해 검증한다. Origin/Host 검사와 포트 바인딩은 실제 uvicorn을 랜덤 포트로 띄워 통합 테스트로 확인한다.

- **인증**: 헤더 없음은 401, 잘못된 토큰은 401/403이다. 대화형 토큰과 잡 토큰은 각각 정상 응답한다.
- **스코프**: 대화형 토큰의 `list_tools` 결과에 J 도구가 없어야 하고, J 도구를 강제로 `call_tool`하면 403이다. 잡 토큰으로 I 도구를 호출하면 403이다.
- **Origin/Host**: evil origin이나 evil host이면 거부한다. `127.0.0.1:<port>`와 `localhost:<port>`만 허용한다.
- **경계값**
  - `limit=51` → 에러
  - `message_ids` 101개 → 에러
  - `body_text` 4001자 → 에러
  - regex 201자 → 에러
  - `get_message`는 20,000자에서 잘린다
- **발송 정책**
  - `disabled`이면 거부한다.
  - `confirm`이면 FakeClock 120초 뒤 `pending_approval`이 된다.
  - `allowlist`이면 허용 목록은 바로 발송하고, 나머지는 거부한다.
- **잡 토큰 생명주기**: 잡이 끝난 뒤 재사용하면 거부한다. mcp.json이 삭제되는지 확인하고, POSIX에서는 권한 비트도 검증한다.
- **감사로그**: 성공한 호출과 거부된 호출 모두 1건씩 기록된다.
- **실제 Claude Code 연동**: e2e_claude 마커를 붙인다.

## 6. 자동 업데이트 테스트

### 모듈 분리 제안

| 모듈 | 역할 |
|---|---|
| `update/version.py` | 순수 SemVer 처리 |
| `update/release_client.py` | base_url을 주입받는다 |
| `update/verifier.py` | 해시와 서명 검증 |
| `update/installer.py` | 플랫폼별 설치 |
| `update/rollback.py` | 롤백 |

### 가짜 GitHub Releases 서버

`fake_github_releases.py`가 `/repos/<o>/<r>/releases/latest`와 `/releases`를 흉내 낸다. 응답은 실제 API 스키마를 따르는 JSON이고, 더미 자산 파일과 체크섬, 서명도 함께 내려준다.

### 버전 비교

| 현재 | 최신 릴리스 | 기대 결과 |
|---|---|---|
| 0.0.0 | 0.0.1 | 업데이트 있음 |
| 0.0.1 | 0.0.1 | 업데이트 없음 |
| 0.1.0 | 0.0.9 | **거부** |
| 0.1.0 | 0.2.0-beta.1 | 기본 채널에서는 무시하고, 옵트인한 경우에만 후보로 삼는다 |
| 0.2.0-beta.1 | 0.2.0 | 업데이트 있음 |
| 0.2.0-beta.1 | 0.2.0-beta.2 | 업데이트 있음 |

- draft 릴리스는 제외한다.
- `v` 접두가 붙은 태그도 파싱한다.
- SemVer가 아닌 태그는 크래시 없이 건너뛴다.

### 다운그레이드

일반 경로에서는 항상 거부한다. 사용자가 명시적으로 강제 재설치나 롤백을 고른 경우만 별도 경로로 허용한다.

### 해시/서명 불일치

| 상황 | 기대 동작 |
|---|---|
| SHA256 불일치 | 중단하고 파일을 삭제한 뒤 알린다 |
| 서명 없음 | 기본 차단 |
| 신뢰하지 않는 키로 서명됨 | 거부 |
| MITM이 체크섬을 변조함 | 거부 |

### 중단과 롤백

- 다운로드가 끊겨도 원자적 rename을 쓰므로 기존 설치는 손상되지 않는다.
- 디스크가 부족하면 기존 버전을 유지한다.
- 적용한 뒤 `--version` 헬스체크가 실패하면 자동으로 롤백한다.
- 적용 도중 강제 종료되면, 다음 기동 때 staging 플래그를 확인해 완료하거나 롤백한다.

## 7. CI (GitHub Actions)

- **기본 매트릭스**: windows-latest와 macos-latest, Python 3.12, `QT_QPA_PLATFORM=offscreen`.
- **docker 테스트**: GreenMail은 별도 ubuntu-latest job에서만 돌린다.
- **e2e_claude**: `workflow_dispatch`로 수동 실행하며, 실패해도 파이프라인을 막지 않는다.
- **build-smoke job**: 두 OS에서 PyInstaller로 빌드한 뒤 결과물에 `--version`을 실행한다. exit 0이고 출력에 기대 버전이 들어 있어야 통과한다.
- **최적화와 리포트**: pip와 PyInstaller 캐시를 쓰고, pytest-cov xml 리포트를 남긴다.

## 8. Phase별 완료 기준 / 커버리지

| Phase | 기준 | 커버리지 |
|---|---|---|
| P0 | config/storage/migration 단위 테스트, 단일 인스턴스, offscreen 창 스모크, 두 OS CI 녹색 | config·storage·migrations 80% 이상 |
| P1 | mime/charset/sanitize/incoming/outgoing 단위 테스트, aiosmtpd와 fake POP3/IMAP 통합, 한글 fixture 17종, UI 스모크, PyInstaller 스모크 | mail/storage 85% 이상, 전체 70% 이상 |
| P2 | 3장 매트릭스 전부 | mcp_server 90% 이상(분기 포함), 전체 75% 이상 |
| P3 | 규칙/LoopGuard/RateLimit 경계값, 드라이런, fake_claude 15종, 인젝션 100% 차단(1건이라도 실패하면 불통과), 실제 claude 2건 | rules·autoreply 90% 이상, 전체 80% 이상 |
| P4 | IMAP IDLE·폴더 GreenMail, stdio 프록시 왕복, Desktop 수동 체크리스트 | 전체 80% 이상 |
| P5 | 6장 매트릭스 전부. 다운그레이드, 해시 불일치, 서명 불일치는 모두 거부하고 실패 시 자동 롤백 | update 90% 이상, 전체 80% 이상 |

**전제 조건**: Edison은 0장의 DI 제안(Clock, ProcessRunner, ShellProbe, SecretStore, base_url 주입)을 반영해 구현해야 한다.
