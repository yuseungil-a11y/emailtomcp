# EmailToMCP 2차 보안수정 결과 (N-1/R-1, N-2, N-3, N-4) — Edison

## 요약
데카르트(R-1)와 Spinoza(N-1, N-2)가 독립적으로 찾아낸 발송경합/UNC 유출 취약점과 Spinoza의 Low 2건(N-3, N-4)을 모두 수정했습니다. N-1은 권고안 ①원자화 ②소유권 회수 ③저장실패시 발송중단을 모두 적용했습니다. 신규 회귀테스트 9건 포함 134 passed. 전체 스위트는 미실행. git 커밋은 안 함(Newton 위임 대상).

## N-1 / R-1 (Medium) — 세 가지 모두 적용

**① 저장과 발송을 하나의 writer 트랜잭션으로 통합 (핵심)**
- `storage/repositories/drafts.py`: 저장 SQL을 `_apply_compose_fields()`로 분리. 신규 `save_compose_and_mark_outbox()`가 writer 작업 하나 안에서 BEGIN→화면내용 UPDATE(status='draft'일 때만)→draft_recipients 재작성→message_id_hdr/approved_by='user_send' 기록→transition(draft→outbox) 순으로 커밋. 초안이 draft 상태가 아니면 롤백+False(내용·상태 불변).
- `mail/draft_service.py`에 동일 서비스 메서드 추가(주소 중복제거·정규화 포함).
- `app.py` `send_draft_now(draft_id, *, to_addrs, cc_addrs, bcc_addrs, subject, body_text, attachments)`: 화면 내용을 필수 인자로 받음. DB값을 그대로 보내던 예전 경로(mark_outbox 단독호출)는 의도적으로 제거(fail-closed).
- `compose_window.py` `_on_send`: `_autosave()` 호출 제거, `_collect_fields()` 결과를 `send_draft_now(draft_id, **fields)`로 한 번에 전달.

**② 소유권 회수 (추가 방어)**
- `revert_approval_to_draft(..., hand_over_to_user=False)`: [수정후발송](cancel_for_edit)일 때만 같은 트랜잭션에서 origin='user'로 변경(mcp_token_id는 감사추적용으로 유지, H-1의 require_mcp_owned가 이후 보호). 거부/만료/무효화 때는 바꾸지 않음(Claude가 계속 고칠 수 있어야 함).
- `approval.py`의 cancel_for_edit/_resolve에 hand_over_to_user 전파.
- 이 변경으로 "origin은 생성 후 불변" 전제가 깨지므로, **writer 안에서 소유권을 한 번 더 확인**하도록 보강: update_compose/delete_draft repo·서비스에 `mcp_owner_token_id` 추가(WHERE에 `AND origin='mcp' AND mcp_token_id=?`), MCP update_draft/delete_draft가 이 값을 전달. `ApprovalService.request(draft_id, owner_check=None)` 추가로 confirm 경로도 writer 안에서 require_mcp_owned 재확인(allowlist 경로는 기존에 이미 재확인 중).

**③ 저장 실패 시 발송 중단**
- 저장이 발송 트랜잭션 안으로 들어가 저장 실패 시 전이도 안 일어남. 작성창은 평문 오류창을 띄우고 열린 채 유지, [보내기] 버튼 재활성화. `_autosave()`는 bool 반환으로 바뀌어 자동저장/취소/닫기 용도로만 사용.

**선택 이유**: ①만으로 끼어들기 틈이 구조적으로 제거됨(writer 단일스레드). ②로 사용자 편집 중 MCP가 내용을 바꾸는 것 자체를 차단. ③은 ①의 부산물로 자연 해결. 스냅샷해시 대조 방식은 검토했으나 "보이는 것만 나간다"를 오류 없이 보장하는 현재 방식을 선택.

## N-2 (Medium) — PlainText 헬퍼 일괄 적용
- 신규 `ui/message_box.py`(plain_warning/plain_information/make_plain_message_box, setTextFormat(PlainText) 지정 QMessageBox 인스턴스).
- 주소 오류창(_validate_before_send 결과)에 적용. 외부문자열(예외/경로/서버상태) 들어가는 QMessageBox 총 23곳 적용: compose_window, main_window, send_approval_dialog, account_dialog, mcp_panel.
- 고정문구만 있는 메시지는 유지(account_dialog의 "지원예정" 안내는 기존 테스트가 QMessageBox.information을 monkeypatch해서 그대로 둠).
- **하지 않은 것**: 회신 수신주소 addr-spec 정규식 필터링(근본대책) — 회신수신자 생성코드가 mail/mime/build.py 쪽이라 범위 밖, 평문표시만으로 로드경로는 제거된다고 판단. 후속과제로 남김.

## N-3 (Low) — asgi_host.py
- server.serve()를 안쪽 try/finally로 감싸 순서를 **on_exit→소켓close→lifespan __aexit__**로 변경. `_notify_exit()`로 on_exit 정확히 1회만 호출. lifespan 진입 자체 실패는 바깥 finally가 처리.

## N-4 (Low) — tools_draft.py require_mcp_owned
- principal.token_id is None이면 즉시 PolicyError(fail-closed). Spinoza의 부가권고(초안 INSERT에 mcp_token_id 동시기록 원자화)는 하지 않음 — 이번 writer측 소유권 조건이 그 공백을 메운다고 판단.

## 회귀테스트 (신규 9건)
- `test_mcp_tools.py`(+5): N-1 넘겨받은 후 원토큰 update/send/delete 거부, writer측 소유권가드가 stale 체크 차단, compose발송이 화면내용만 원자적으로 outbox에 반영(외부BCC 미포함)+전이후 update_draft 거부, draft상태 아닐때 compose발송 무효, N-4 token_id None 주체 거부.
- `test_dialogs_smoke.py`(+3): compose발송이 별도 update_compose 없이 fields를 한번에 전달, 비정상주소 오류창이 mightBeRichText=True인데도 textFormat=PlainText이고 발송요청 미발생, 저장실패 시 평문으로 보고.
- `test_mcp_http_binding.py`(+1): on_exit가 lifespan정리 전·정확히 1회 호출(이벤트순서 [enter, on_exit, aexit]).
