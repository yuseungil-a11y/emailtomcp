# EmailToMCP P2 보안수정(Edison, 12번 문서) 재확인 — Spinoza

## 검토 방법
Edison 보고서(12번)는 참고만 하고 판단은 실제 코드를 읽고 내림. email.utils.getaddresses의 따옴표 local-part 보존, Qt.mightBeRichText 판정 로직은 직접 실행으로 실측. pytest는 관련 3개 파일(test_mcp_tools, test_mcp_tokens_ratelimit, test_mcp_core)만 실행, 51건 통과.

## 결론
- 지적했던 6건은 모두 의도대로 고쳐졌음. **H-1, H-2, M-2는 완전해결.** H-3, M-1, M-3에는 작은 잔여 틈.
- **새 Medium 2건**: N-1(Edison이 "L-7 유형 잔존"으로 적은 건이 실제로는 승인 없는 유출 경로), N-2(QMessageBox에 메일에서 온 문자열이 들어가는 곳 1군데, Edison 보고와 다름).
- Critical/High 없음.

## 새로 발견한 문제

### Medium

**N-1. 작성창에서 "저장→발송"이 원자적이지 않음 — 승인·레이트리밋 없이 외부 BCC 유출 가능** (데카르트의 R-1과 동일 건, 독립적으로 확인)
- 위치: compose_window.py:347-376(_on_send가 _autosave() 후 별도로 send_draft_now 호출), app.py:734-750(mark_outbox가 내용확인 없이 draft→outbox, approved_by=user_send)
- 공격 시나리오: ①공격자 토큰(read+draft만)이 회신 초안 생성 ②사용자가 작성창에서 열거나 승인창 [수정후발송] 클릭(send_draft 응답 decision=edit가 공격자에게 타이밍 신호) ③공격자가 update_draft(bcc=[외부])를 반복호출(호출제한 없음) ④autosave와 mark_outbox 사이에 공격자 writer작업이 끼어들면 화면에 없던 BCC가 send스코프·승인·레이트리밋 없이 발송.
- 추가: _autosave 실패해도 경고로그만 남기고 발송 계속(compose_window.py:333-334) — 이 경우 DB의 공격자 버전이 그대로 나감.
- 수정방안: ①send_draft_now(draft_id, fields)를 writer 작업 하나로 통합(권장) ②작성창이 보여준 스냅샷해시를 넘겨 writer 안에서 대조 ③MCP초안을 사용자가 넘겨받는 시점(cancel_for_edit/작성창 열기)에 origin→user 또는 mcp_token_id 비우기 ④autosave 실패 시 발송 중단.

**N-2. 작성창 주소검증 오류 QMessageBox(AutoText)에 메일 원본 주소가 들어감 — 원클릭 UNC 로드 가능성**
- 위치: compose_window.py:336-350(_validate_before_send → QMessageBox.warning)
- 실측: 공격자 메일 Reply-To를 `"<img src=//evil/s/a.png>"@evil.com`으로 하면 getaddresses가 그대로 보존 → 회신 초안 To에 들어감. 공백 있어 _ADDR_RE에 걸려 오류창에 반드시 표시. mightBeRichText(해당 오류문구)==True 실측 확인.
- 영향: 공격자 메일에 회신 후 [보내기] 한 번으로 이미지(UNC) 로드 시도 가능. MCP의 create_reply_draft로 만든 초안도 동일.
- Edison의 "메일유래 문자열이 들어가는 QMessageBox는 없음" 판단은 이 지점에서 틀림.
- 수정: 해당 QMessageBox를 인스턴스화해 setTextFormat(PlainText) 지정. 근본적으로는 회신 초안 생성 시 수신주소를 addr-spec 정규식으로 걸러 이상 주소 차단/경고. 다른 `f"...: {exc}"` 패턴 QMessageBox도 동일한 PlainText 헬퍼로 일괄 적용 권고(첨부 관련 예외는 sanitize_filename이 `<>` 제거해 현재 안전).

### Low
- **N-3**: asgi_host._serve에서 uvicorn 종료 시 lifespan_cm.__aexit__ 완료 후에야 on_exit 호출돼, 그 사이 current_port()가 닫힌 포트를 알려줄 수 있음. 로컬공격자가 그 창에 포트선점+핸드셰이크까지 겹쳐야 해서 Low. 수정: on_exit를 lifespan 정리보다 앞, 소켓close보다 앞에서 호출.
- **N-4**: require_mcp_owned가 token_id None끼리는 동치로 통과(fail-open). 현재 authenticate는 항상 token_id를 채우므로 실악용 불가하나, P3 job 주체(token_id None 가능) 도입 시 위험. 수정: principal.token_id is None이면 즉시 거부, 초안 생성 INSERT에 mcp_token_id 동시 기록으로 원자화.
- **N-5**: 계정상태 ToolTip(AutoText, main_window.py:1073, folder_tree_model.py:115)에 서버 응답문자열이 그대로 들어감. 마우스오버 필요+악성서버 전제라 Low. 수정: html.escape 또는 평문처리.
- **N-6**: M-1 메모리카운터가 벽시계 기준이라 시스템시계 역행 시 만료 안 됨 — 공격자가 유발 불가한 조건이라 실제위험 없음으로 판단.
- **N-7**: M-1 쿨다운이 초안단위(M-1 부분해결 사유와 동일). 토큰단위 지수백오프(거부2회째부터 5분) 권고.

### 문제없음으로 확인
- require_mcp_owned 오류메시지: read스코프 list_drafts로 이미 보이는 정보라 추가노출 아님.
- count_pending_approvals/레이트카운터: Python int 오버플로 없음, writer직렬화+self._lock 아래 처리로 레이스 없음, lock 안에서 writer 미호출로 데드락 없음, _request_times는 deque 길이 5 이하로 메모리 문제 없음.
- 승인창 QMessageBox의 outcome.message: 고정문구로 안전. 링크열기 확인창도 mightBeRichText==False 실측 확인.

## Edison의 "남은 위험" 재평가
| 항목 | Edison 평가 | 재평가 |
|---|---|---|
| UNC 실제 로드 미실측 | 참고 | 지적했던 위젯은 PlainText라 그 부분은 해결로 봄. N-2 지점에서 실측 필요(현재 Medium 가정) |
| MCP초안 경합(L-7 유형) | 범위밖, 잔존 | **Medium(N-1)으로 상향.** 승인·send스코프 우회 유출경로이고 공격자가 decision=edit로 타이밍신호까지 받음 |
| QMessageBox 일부 AutoText | 메일유래 문자열 없음 | **틀림.** N-2 존재. 나머지는 안전 또는 Low |

## 권장 조치 순서
1. N-1: 작성창 발송 원자화 + MCP소유권 해제(Opus 권장, 발송경로 변경)
2. N-2: QMessageBox PlainText 헬퍼 일괄적용 + 회신주소 정규식 필터링 + UNC 로드 실측
3. N-3, N-4 순서 및 fail-closed 보정
4. N-5~N-7은 다음 정리 때
5. 회귀테스트: 저장-발송 사이 update_draft 끼워넣기 거부 확인, 따옴표주소 오류창 평문표시 확인, lifespan종료중 current_port() None 확인, token_id None 주체 거부 확인
