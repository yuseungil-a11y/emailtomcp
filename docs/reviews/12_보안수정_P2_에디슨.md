# EmailToMCP P2 보안검토(Spinoza, 11번 문서) 조치 — Edison

## 요약
Spinoza가 지적한 High 3건(H-1, H-2, H-3), Medium 3건(M-1, M-2, M-3)을 모두 수정했습니다. 회귀 테스트 16건을 추가했고, 관련 파일 15개(125건) 테스트가 전부 통과했습니다(21초, 전체 스위트는 지시대로 돌리지 않음). DESIGN.md §0.3/§6.1~§6.4/§7.7/§11.5/§11.6/§12.3과 인앱 매뉴얼(05/06/07)도 함께 갱신했습니다. git 커밋은 하지 않음(Newton 위임 대상).

## 수정 내용

### H-1: MCP 도구가 사용자 초안을 건드릴 수 있던 문제
- `tools_draft.py`에 `require_mcp_owned(draft, principal, action)` 추가 — 초안이 `origin=='mcp'`이고 `mcp_token_id`가 요청 토큰과 같을 때만 통과, 아니면 `PolicyError`.
- `update_draft`, `delete_draft`, `send_draft`(`tools_send._precheck`) 모두에 적용. allowlist 발송은 writer 안에서 한 번 더 확인.
- `list_drafts`/`get_draft_status`는 읽기이므로 그대로 허용(변경만 차단).
- 부작용: 토큰 재발급 시 이전 토큰이 만든 초안은 MCP로 다룰 수 없게 됨(사용자가 앱에서 직접 처리 필요) — 문서화함.

### H-2 + M-2: allowlist 판정 TOCTOU, 첨부 있는 초안 confirm 누락
- `tools_send.py`에 `allowlist_requires_confirm`(첨부 있으면 종류 무관 항상 True), `allowlist_violation(draft, mode, allowlist)` 추가.
- `send_draft`는 읽기 스냅샷 판정을 "빠른 길 선택" 용도로만 사용. 실제 판정은 `_policy_check` 콜백이 `ApprovalService.send_by_policy(draft_id, policy_check)`로 전달.
- `approval.py`의 `send_by_policy`는 `policy_check`를 **필수 인자**로 변경(fail-closed). writer가 방금 읽은 draft 행 기준으로 소유권·발송모드(재조회)·허용목록·첨부유무 4가지를 재판정, 위반 시 PolicyError(상태는 draft 유지).

### H-3: 비신뢰 문자열 리치텍스트 렌더링
- `send_approval_dialog.py`: `_plain_label()` 헬퍼로 이 창의 QLabel 전부를 PlainText화(주소/제목/계정표시명/외부배지/헤더/카운트다운/QFormLayout 행이름 포함).
- `main_window.py`: 미리보기 QLabel 3개(제목/보낸사람/받는사람) + 상태줄 QLabel 7개도 PlainText화. **Spinoza 보고서 범위 밖이었으나, 메일 선택만으로 UNC 로드가 가능했던 더 넓은 공격면**이라 함께 처리. grep으로 main_window 전체에 AutoText 잔존 없음 확인.
- 범위 밖이지만 같은 유형이라 `account_dialog.py`의 연결테스트 결과 라벨 2개도 PlainText화.
- **UNC 실제 로드 여부 실측은 미수행** — 코드상 원인은 제거됐다는 설명.

### M-1: 승인 요청 폭주
- `drafts.request_approval`에 `verify` 인자 추가, writer 안에서 직렬화 검사: 토큰당 동시 pending_approval 3건(DB기준, `count_pending_approvals` 신설) / 분당 요청 5건(메모리) / 거부 초안 재요청 60초 쿨다운(메모리).
- 상수: `approval.py`의 `MAX_PENDING_PER_TOKEN`, `MAX_REQUESTS_PER_MINUTE`, `REJECT_COOLDOWN`.
- 주의: 분당 상한·쿨다운은 메모리 기준이라 앱 재시작 시 초기화됨(동시대기 3건 상한은 DB라 유지).

### M-3: 핸드셰이크 포트 상태 신선도
- `asgi_host.py`에 `on_exit` 콜백 추가(`_serve` finally에서 호출).
- `app.py`의 `McpServiceRunner`: `current_port()`는 상태 플래그+`host.running`(태스크 생존)까지 확인. 호스트 예기치 않은 종료 시 즉시 상태 하강+error 이벤트(stop()에 의한 정상종료는 중복이벤트 없음). `stop()`은 running=False를 먼저 알린 뒤 `host.stop()` 호출. `start()`는 시작 직후 이미 죽었으면 running=True로 알리지 않음.
