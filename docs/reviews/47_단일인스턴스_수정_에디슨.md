# 단일 인스턴스 실행 버그 수정 — Edison

## 요약
`SingleInstanceGuard`는 원래부터 app.py에 있었음(신규구현아님) — P2보안검토 L-1에서지적된결함(소켓/파이프이름사용자별아님, listen()결과미확인)이그대로남아있던케이스. 둘다수정+관련버그(활성화신호유실가능성)추가발견·수정.

## 조사결과
`local_handshake.py`의named pipe/소켓은 **MCP핸드셰이크전용이아니라 "단일인스턴스보장"+"MCP핸드셰이크중계" 겸용으로의도적설계**됨(DESIGN.md §2(a)/§6.4, "허용명령은activate와mcp_handshake두가지뿐(L2)"). 두용도분리리팩토링은안함(의도된설계, 과도한변경방지). **실제단일인스턴스판정은QLockFile**(데이터디렉터리별잠금파일)이함. QLocalServer(named pipe)는 그승자가"활성화요청"+"MCP핸드셰이크중계"받는보조채널일뿐. QLockFile자체는이환경서매우견고(두프로세스를같은데이터디렉터리로거의동시에수십회띄워도둘다"첫인스턴스"로판정된적없음).

## 확인된버그(L-1그대로)
`SingleInstanceGuard.try_acquire()`:
1. **listen()반환값미확인**: `self._server.listen(self._key)` 호출만하고결과버림 — QLockFile.tryLock()성공(데이터디렉터리기준첫인스턴스)인데 listen()실패(권한문제,리소스고갈등)하면 활성화신호·MCP핸드셰이크중계받을방법없이조용히계속진행.
2. **파이프이름이사용자별로구분안됨**: SINGLE_INSTANCE_KEY="EmailToMCP-single-instance"가전역고정문자열 — 같은PC다른Windows계정인스턴스와이름겹칠수있음.

(조사메모: Windows named pipe는같은이름으로여러서버가동시에listen()할수있음을실측확인 — "이름충돌"만으론listen()실패재현불가, 테스트는몽키패치로강제. 즉listen()실패는실전에서이름충돌보다권한/리소스고갈시나리오에더해당할가능성큼.)

## 추가발견버그(활성화신호유실)
"진쪽"인스턴스가보내는activate신호가 run_app()에서app.exec()(Qt이벤트루프)가아직한번도돌기전에전송·종료되는구조라, 이PC·PySide6 6.11실측상waitForBytesWritten/waitForDisconnected가완료통지없이False반환하는경우있었고, 그대로프로세스끝나면"activate"바이트가상대에게전달되기전에날아갈수있음(=두번째실행시기존창이활성화안되고조용히사라짐). QApplication.processEvents()로짧게펌핑하도록수정.

## 수정내용
- `local_handshake.py`: getpass.getuser()로현재OS사용자얻어SINGLE_INSTANCE_KEY에섞도록변경(`EmailToMCP-single-instance-<사용자명>`, 사용자명못얻는드문경우는공용이름으로폴백). app.py의자체복제상수제거하고local_handshake.SINGLE_INSTANCE_KEY하나만쓰도록통일.
- `app.py`(SingleInstanceGuard.try_acquire): listen()반환값확인, 실패시경고로그남기되**앱기동자체는안막음**(가용성/DoS방지우선, 토큰유출문제아니므로"일부보호약화"선택). self._server는None으로정리. activate전송경로에QApplication.processEvents()펌핑추가+waitForDisconnected보강. 클래스docstring에"실제판정은QLockFile, QLocalServer는보조채널"관계명시.

## 실측메모
실제빌드exe+dev venv양쪽서 같은데이터디렉터리로두프로세스거의동시에(수십회)띄우는테스트반복했으나 QLockFile자체가두번다성공하는경우한번도재현못함. EMAILTOMCP_DATA_DIR을다르게준경우(멀티프로파일,의도된기능)는각자정상DB마이그레이션수행하고 전역자원MCP기본포트(8765)만충돌(WinError10048,설계대로경고후MCP비활성정상기동) — 이건버그아니라의도된동작. **사용자가본"두PID동시생존"현상의정확한트리거는100%재현못했지만, Spinoza L-1이지적한두결함은코드상명백히존재했고그대로고쳤음.** 이PC서재현안됐다고사용자환경에서안전보장은아니니, 같은증상재발시 "단일인스턴스로컬서버바인딩에실패했습니다" 경고로그가찍히는지확인필요(찍히면이번에고친경로가실제발동한것).
