## 1. Velopack 통합
`__main__.py`에 `run_velopack_hook()` 추가(main() 맨앞, argparse보다먼저, PyInstaller번들일때만동작, velopack패키지없으면건너뜀). `App().set_auto_apply_on_startup(False).run()` 형태 — **업데이트자동적용을 끔(§14.2상 서명매니페스트가판단해야함, 설계원문에서 추가된부분이라확인필요**). `packaging/release/build_velopack.py`(신규): dist/를 vpk pack으로패키징, 버전SemVer2변환, stable/rc채널분리, `--dry-run`확인됨. pyproject.toml에 release extra(pyinstaller==6.22.3, velopack==1.2.161) 추가.

## 2. 후보매니페스트생성 — `build_manifest.py`
`--artifact PLATFORM:ARCH:KIND:PATH` 또는 `--scan PLATFORM:ARCH:DIR`(파일명끝부분으로분류, 이번버전아닌nupkg제외). 버전은_version.py에서읽고 정규형아니거나.dev/+붙으면중단, `--expect-tag`로태그대조. 저장전 pydantic자체검증(extra=forbid)+stable채널rc금지+floor>latest거부+64KB상한+LF만허용. 공용모듈`release_common.py`가 앱의update.manifest/version 재사용(packaging폴더명이 PyPI packaging라이브러리와겹쳐 스크립트실행방식사용).

## 3. `.github/workflows/release.yml`(신규)
validate→build(windows-latest,macos-latest)→draft-release. validate: .dev태그는즉시성공종료, 형식틀린태그는실패, 작업트리clean확인+_version.py태그일치검증(샘플8개로태그판정확인됨). build: PyInstaller빌드+--version스모크, Windows는vpk설치해패키징, macOS는onedir를zip(app_zip)만. SBOM은pip list --format=json수준. draft-release: manifest-candidate.json생성(rc태그는생략), SHA256SUMS.txt+attest-build-provenance+gh release create --draft. Actions는git ls-remote로커밋SHA고정, 별도PAT대신job범위GITHUB_TOKEN사용. 검증은문법까지만(PyYAML파싱, run블록14개는bash -n, 내부파이썬은ast.parse).

## 4·5. 오프라인서명·재서명 — `sign_release.py`
신규서명(`--candidate --artifacts-dir --key`): ①산출물마다크기·sha256재계산해후보대조(불일치전부모아표시후중단) ②issued_at=지금,expires=30일뒤 ③서명내용표시+y/N확인(--yes로생략가능) ④minisign -S서명(trusted comment: app=EmailToMCP channel=stable version=<v> issued=<ts>) ⑤**결과를 앱내장K1공개키+앱의verify_manifest로재검증**(다른키로서명했으면실패+결과파일미생성, 임시이름후교체방식이라기존파일보존).
재서명(`--resign <기존stable.json>`): **추가안전장치2가지** — 기존.minisig를내장키로먼저검증(통과해야재서명, Pages변조본에재서명하는사고방지), PC시계가기존issued_at보다늦지않으면중단(클라이언트롤백거부대응), issued_at/expires외내용불변확인.
