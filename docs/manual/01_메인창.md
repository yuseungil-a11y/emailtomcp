# 메인 창

메인 창은 **메뉴 · 툴바 · (폴더 트리 | 메일 그리드 / 미리보기) · 상태줄**로
구성됩니다.

## 메뉴/툴바

- **파일**: 종료.
- **메일**: 받기(`F5`), 새 메일(`Ctrl+N`), 회신(`Ctrl+R`), 전체회신
  (`Ctrl+Shift+R`), 전달(`Ctrl+L`), 삭제(`Delete`), 읽음/안읽음 전환, 플래그 전환.
- **도구**: 계정, [규칙 설정](04_규칙설정.md)(자동회신 규칙), 설정.
- **Claude**: **Claude/MCP 패널**(Claude Code 연결·토큰·감사 로그 —
  [05_Claude_MCP패널.md](05_Claude_MCP패널.md)), **MCP 서버 상태**(서버 포트와 Claude
  연결 여부를 작은 창으로 보여 줍니다), **승인 대기 목록**(아래 "승인 대기"로 이동).
- **도움말**: 이 사용 설명서(`F1`), **업데이트 확인**(지금 바로 새 버전이 있는지
  확인하고 결과를 알려 줍니다), **로그 폴더 열기**(디버깅용 로그 파일이 쌓이는
  폴더를 파일탐색기로 엽니다 — 매일 자정 새 파일로 바뀌고 최근 7일분만 보관됩니다.
  비밀번호·토큰·메일 본문 같은 민감한 내용은 로그에 평문으로 남지 않습니다 — 아래
  "로그의 에러코드(`EMCP-XXXX`)" 참고), 정보.
- 툴바에는 메일 메뉴의 주요 동작과 **검색창**, **필터**(전체/안읽음/플래그/
  첨부있음), **긴급정지**가 있습니다. 긴급정지는 자동회신이 꺼져 있으면 비활성이고
  (마우스를 올리면 "자동회신이 꺼져 있습니다"), 켜져 있을 때의 실제 동작은 이후
  단계에서 제공됩니다.

### 로그의 에러코드(`EMCP-XXXX`)

로그에 `초안 5 발송 일시 오류, 재시도 예정: SMTP 통신 실패: ... [EMCP-2005]`처럼
`EMCP-`로 시작하는 코드가 붙어 있는 줄을 볼 수 있습니다. 메일수신·발송 실패,
MCP 서버 시작 실패, 자동업데이트 서명검증 실패 같은 **예외/오류 상황에만** 붙는
고정 코드로, 코드 앞자리(천 단위)에 따라 분야를 구분합니다(`1xxx`=메일수신,
`2xxx`=메일발송, `3xxx`=MCP 서버, `4xxx`=저장소/DB, `5xxx`=자동업데이트,
`6xxx`=UI, `9xxx`=분류되지 않은 일반 오류). 평범한 정보성 로그(예: "계정 1
수신 동기화 완료")에는 붙지 않습니다. 문제를 문의할 때 이 코드를 함께 알려
주시면 원인 파악이 더 빨라집니다.

## 업데이트 배너(툴바 아래, 필요할 때만 표시)

새 버전이 확인되면 툴바 바로 아래에 배너가 나타납니다. 평소에는 보이지 않습니다.

| 배너 | 뜻 | 닫기 |
|---|---|---|
| 파란색 "새 버전 X.Y.Z이(가) 있습니다." | 새 버전이 있습니다 | **[나중에]** — 그 버전에 대해서는 다시 띄우지 않습니다(더 새 버전이 나오면 다시 뜹니다) |
| 주황색 "보안 업데이트 X.Y.Z이(가) 있습니다." | 보안 수정이 들어간 새 버전입니다 | **[나중에]** — 24시간 뒤 다시 표시됩니다 |
| 빨간색 "필수 업데이트: …" | 지금 버전이 지원되는 최소 버전보다 낮습니다 | 닫을 수 없습니다(업데이트하면 사라집니다) |
| 연보라색 "7일 넘게 업데이트를 확인하지 못했습니다." | 업데이트 확인이 계속 실패하고 있습니다 | **[나중에]** — 앱을 다시 시작할 때까지 숨깁니다 |

- **[릴리스 노트]**: 새 버전의 요약(무엇이 바뀌었는지)을 보여 줍니다. 그 창의
  [릴리스 페이지 열기]로 GitHub 릴리스 페이지를 열 수도 있습니다.
- **[다운로드 페이지 열기]**: GitHub 릴리스 페이지를 시스템 브라우저로 엽니다.
  거기서 설치 파일을 받아 직접 실행하세요(앱 안 자동 설치는 이후 버전에서 제공).
  안전을 위해 `https://github.com/yuseungil-a11y/emailtomcp/releases/` 아래
  주소만 열립니다.
- 자세한 설정과 대응 방법은 [설정 > 업데이트 탭](07_설정.md)을 보세요.

## 폴더 트리(왼쪽)

- 계정마다 받은편지함 · 보낸편지함 · 임시보관함 · 휴지통이 나오고, IMAP
  계정이면 서버의 다른 폴더도 함께 표시됩니다.
- 폴더 이름 옆 숫자는 **안읽음 개수**입니다. 예) `받은편지함(3)`.
- **계정 이름 옆의 점**은 그 계정의 메일 서버 연결 상태를 보여줍니다.
  - `●정상`(파란색): 가장 최근 수신/발송이 성공했습니다.
  - `●연결중`(연보라색): 아직 한 번도 확인되지 않았습니다(앱을 막 실행했을 때).
  - `●오류`(빨간색): 가장 최근 수신 또는 발송이 실패했습니다. 점 위에 마우스를
    올리면 오류 메시지를 볼 수 있습니다.
  - 이 상태는 앱을 다시 시작하면 "연결중"으로 초기화됩니다(디스크에 저장되지
    않는 실행 중 상태입니다).
- **작업** 그룹에는 모든 계정을 합친 **보낼편지함**(발송 대기·발송중·실패·결과불명
  초안 수)과 **승인 대기**(Claude가 발송을 요청해 사용자 승인을 기다리는 메일 수)가
  있습니다.
  - **승인 대기**를 클릭하면 미리보기 영역에 목록이 나옵니다. 항목을 더블클릭하거나
    **[승인 창 열기]**를 누르면 [발송 승인 창](06_발송승인.md)이 열립니다.
    **[취소(초안으로)]**는 발송하지 않고 초안으로 되돌립니다(거부와 같습니다).
  - 승인 대기 메일은 24시간이 지나면 자동으로 초안으로 돌아갑니다.

## 메일 그리드(가운데)

열 구성은 **안읽음 | 플래그 | 첨부 | 우선순위 | 보낸사람 | 제목 | 받은시간 | 크기
| 자동회신**입니다. "자동회신" 열에는 자동회신 처리 결과(무시·차단·대기·작성 중·초안·
건너뜀·실패·취소)가 표시됩니다. 평가 대상이 아닌 메일(자동회신을 켜기 전에 받은 메일 등)은
빈 칸입니다. 자세한 내용은 [규칙 설정](04_규칙설정.md)을 보세요.

- 열 머리글을 클릭하면 그 기준으로 정렬됩니다(보낸사람/제목/받은시간/크기/
  우선순위만 정렬 가능).
- 안읽음 메일은 제목이 **굵게** 표시됩니다.
- 목록이 길면 스크롤을 내릴 때마다 200건씩 더 불러옵니다(대량 메일함에서도
  첫 화면이 빠르게 뜨도록 하기 위함입니다).
- 검색창에 3글자 이상을 입력하면 본문까지 포함해 검색하고, 2글자 이하이면
  제목/보낸사람/본문에서 간단히 찾습니다.
- 제목 앞에 `[파싱제한]`이 붙은 메일은 원본이 너무 크거나 복잡해서 안전하게
  일부만 읽어온 메일입니다.

## 미리보기(그리드 아래 또는 오른쪽 — 설정에서 선택 가능)

- 위쪽에 제목 · 보낸사람 · 받는사람 · 날짜가 나오고, 아래에 본문이 나옵니다.
- **[요약]** · **[Claude 초안 만들기]** 버튼은 이번 버전에서는 비활성입니다
  (앱이 직접 Claude를 실행하는 기능으로 P3에서 제공됩니다. 버튼에 마우스를 올리면
  안내가 보입니다). 지금은 Claude Code에서 MCP로 연결해 초안을 만들 수 있습니다
  ([05_Claude_MCP패널.md](05_Claude_MCP패널.md)).
- **[원문 보기]**를 누르면 메일의 원본(.eml) 텍스트를 별도 창에서 그대로
  볼 수 있습니다.
- 첨부파일이 있으면 본문 위에 목록이 나옵니다. 실행 파일 등 위험한 확장자는
  목록에 경고(⚠)로 표시됩니다. 첨부를 더블클릭(또는 오른쪽 클릭 메뉴의
  [저장])하면 원하는 위치에 저장하고, 오른쪽 클릭 메뉴의 [열기]를 누르면
  임시 폴더에 저장한 뒤 바로 엽니다 — 단, **위험한 확장자는 [열기]가
  차단되고 [저장] 후 직접 확인하라는 안내만 뜹니다.**
- 메일의 링크를 클릭하면 바로 열리지 않고, 시스템 브라우저로 열지 확인하는
  창이 먼저 뜹니다(`http`/`https`/`mailto`만 허용).

## 상태줄(맨 아래)

- **메일**: 전체 계정의 연결 상태 집계(`메일 ●정상(2계정)` 또는
  `메일 ●오류(1/2계정)`).
- **MCP**: 내장 MCP 서버 상태입니다.
  - `MCP ●서버:8765`(파란색): `127.0.0.1:8765`에서 실행 중입니다.
  - `MCP ●꺼짐(포트 8765 사용 불가)`(빨간색): 다른 프로그램이 같은 포트를 쓰고 있어
    서버를 켜지 못했습니다. 보안상 다른 포트로 자동으로 바꾸지 않습니다 —
    **도구 > 설정 > MCP**에서 포트를 바꾸고 앱을 다시 시작하세요.
- **Claude**: Claude Code/Desktop이 MCP로 요청을 보내면 `Claude ●연결됨`, 마지막 요청
  후 5분 동안 요청이 없으면 `Claude ●미연결`로 바뀝니다. 서버가 켜져 있어도 Claude가
  아직 요청을 보내지 않았으면 "미연결"입니다.
- **잡 대기**: 자동회신 작업 중 대기·실행 중인 건수입니다. 목록과 사유는
  [Claude/MCP 패널 > 잡 탭](05_Claude_MCP패널.md)에서 봅니다.
- **자동회신**: 자동회신 기능 전체의 켜짐/꺼짐입니다.
  - `자동회신 ○꺼짐`(연보라색): 꺼져 있습니다(기본값). 자동회신 규칙이 평가되지 않습니다.
  - `자동회신 ●켜짐`(파란색): 켜져 있습니다. 켠 이후에 받은 메일에만 규칙이 적용됩니다.
  - 클릭하면 [설정 > 자동회신 탭](07_설정.md)이 바로 열려 켜고 끌 수 있습니다.
- **업데이트**(오른쪽, 버전 표시 옆 — 알릴 것이 있을 때만 보임):
  `업데이트 ●1.0.1`(새 버전 있음), `업데이트 ●필수`(필수 업데이트),
  `업데이트 ●보안 경보`(업데이트 정보 검증 실패 — [설정 > 업데이트 탭](07_설정.md)
  참고). 마우스를 올리면 자세한 내용이 보입니다.

## 중복 실행 방지

EmailToMCP는 한 번에 하나만 실행됩니다. 이미 실행 중인데 다시 실행하면(아이콘을
또 클릭하는 등) 새로 실행한 쪽은 창을 띄우지 않고 바로 종료되고, 이미 떠 있던 창이
앞으로 나와 활성화됩니다 — 창이 두 개로 늘어나지 않습니다.

Claude Code/Desktop과 연동 중이라면 작업 관리자에 `emailtomcp.exe`가 여러 개 보일 수
있는데, 이는 정상 동작입니다 — MCP 연결마다 `--mcp-stdio-proxy` 옵션으로 실행되는 별도
프록시 프로세스가 GUI 창과 별개로 하나 이상 떠 있기 때문입니다([Claude/MCP
패널](05_Claude_MCP패널.md) 참고). 또한 `--data-dir`(또는 `EMAILTOMCP_DATA_DIR`)을
다르게 지정해 실행하면 서로 다른 데이터 영역을 쓰는 별개 인스턴스로 간주되어 함께
실행됩니다 — 이때는 "창이 두 개로 늘어나지 않습니다"의 예외입니다.

## 새 메일 알림

새 메일이 오면(그리고 앱 창이 활성 상태가 아니면) 운영체제 알림(트레이 풍선
도움말)으로 보낸사람과 제목을 보여줍니다.

## 발송 승인 알림

Claude가 메일 발송을 요청하면 운영체제 알림("Claude 발송 승인 요청")과 작업표시줄
깜빡임으로 알려 주고, [발송 승인 창](06_발송승인.md)을 **포커스를 빼앗지 않고**
띄웁니다. 알림을 클릭하면 승인 창으로 이동합니다.
