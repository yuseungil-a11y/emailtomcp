# 규칙 설정(자동회신)

**도구 > 규칙 설정**에서 엽니다. 받은 메일에 어떤 조건이면 **자동으로 답장 초안을
만들지**(또는 무시할지)를 정하는 화면입니다.

> **이번 버전에서 자동회신 결과는 모두 "초안"입니다.** 앱이 답장을 대신 써서
> 임시 초안으로 저장해 두면, 사용자가 직접 검토한 뒤 [보내기]로 보냅니다.
> 사람 확인 없이 바로 보내는 **즉시발송**은 다음 업데이트에서 제공될 예정입니다.

## 이 기능을 쓰려면(claude CLI 필요)

메일검색·초안생성·발송·회신 같은 평소 기능은 **Claude Desktop만으로 완전히
됩니다.** MCP 연결은 Claude Code 전용이 아니라 Claude Desktop도 설정 JSON
(`command`+`args`)으로 똑같은 방식(stdio 프록시)으로 연결되기 때문입니다
([05_Claude_MCP패널.md](05_Claude_MCP패널.md) 참고).

**자동회신(이 화면, 응답 방식을 "Claude가 작성"으로 고른 규칙)만 예외입니다.**
이 기능은 사람이 대화하며 쓰는 게 아니라, 메일이 도착하면 이 앱이 **백그라운드에서
스스로** claude CLI를 한 번 실행해 답장 초안을 만드는 구조입니다. Claude Desktop은
대화창이 열려 있어야 쓸 수 있는 GUI 앱이라 이렇게 혼자 백그라운드에서 켜질 수
없고, 그래서 이 기능을 쓸 때만 **claude CLI**(Claude Code)가 필요합니다. (응답
방식을 "고정 템플릿"으로 쓰는 규칙은 claude CLI 없이도 그대로 동작합니다.)

- 여기서 쓰는 claude CLI는 사람이 터미널에 앉아 대화하는 용도가 아니라, `claude -p`
  (headless/비대화형 모드 — 한 줄 실행하면 결과만 바로 돌려주는 방식)로, 메일을
  받을 때마다 이 앱이 조용히 자동으로 불러 쓰는 **엔진** 역할입니다. **설치 후에는
  사용자가 터미널을 직접 열거나 claude를 쓸 일이 없습니다** — 평소처럼 Claude
  Desktop만 쓰셔도 됩니다.
- **설치는 가볍습니다.** Claude Desktop만 쓰시는 분도 아래 두 단계만 하면 끝입니다.
  1. `npm install -g @anthropic-ai/claude-code`
  2. `claude login` (평소 쓰시는 구독 계정으로 로그인 — 한 번만 하면 됩니다)
- API 키를 발급받아 쓴 만큼 과금하는 방식이 아니라 이렇게 **구독 로그인 기반 CLI**를
  쓰는 이유는, 이 앱이 처음부터 "API 키를 따로 보관하지 않는다"는 원칙으로
  설계됐기 때문입니다 — 평소 쓰던 구독 로그인 그대로 쓰면 되고, 토큰·키를 앱에
  따로 입력하거나 보관할 필요가 없습니다.
- claude CLI 경로를 앱에 고정하는 방법은 [Claude/MCP 패널 > 잡 탭](05_Claude_MCP패널.md)에
  있습니다.

## 자동회신 켜기/끄기(전역 스위치)

규칙은 **자동회신 전역 스위치가 켜져 있을 때만** 적용됩니다. 스위치는
[설정 > 자동회신 탭](07_설정.md)에 있습니다.

- **기본은 꺼짐**입니다.
- 꺼져 있으면 규칙 설정 화면 맨 위에 **"자동회신이 꺼져 있습니다. 규칙은 저장되지만
  적용되지 않습니다."** 안내와 **[설정에서 켜기]** 버튼이 보입니다. 꺼져 있어도 규칙을
  만들고 고치고, 드라이런으로 미리 시험해 볼 수 있습니다.
- **켤 때**: 확인 창이 뜨고, 창이 뜬 뒤 1.5초 동안은 버튼이 눌리지 않습니다(기본 버튼은
  [취소]). 확인하면 켜집니다.
- **켠 이후에 받은 메일에만 적용됩니다.** 꺼져 있는 동안 받은 메일은 다시 켜도 대상이
  아닙니다(소급 적용 없음).
- **끄면**: 대기 중이거나 작성 중이던 자동회신 작업이 바로 취소되고, 결과 창에 건수가
  표시됩니다. 끄더라도 **규칙은 지워지지 않으며**, 다시 켜면 그대로 적용됩니다.
- 계정마다 자동회신 적용 여부를 따로 정할 수 있습니다([계정 설정 > 자동회신 탭](03_계정설정.md)).
  전역 스위치와 계정 설정이 **모두 켜져 있어야** 그 계정의 메일이 평가됩니다.

| 열 | 뜻 |
|---|---|
| 순서 | 위에서부터 차례로 검사합니다. **처음 맞는 규칙 하나만** 적용됩니다. |
| 사용 | 사용 / 중지 |
| 이름 | 규칙 이름 |
| 계정 | 적용할 계정(또는 모든 계정) |
| 동작 | 무시 / 초안 |
| 응답 방식 | Claude 생성 / 고정 템플릿 |

- **[추가] / [편집]**(행을 더블클릭해도 됩니다) / **[사용/중지]** / **[삭제]**
- **[▲ 위로] / [▼ 아래로]**: 검사 순서를 바꿉니다.
- 규칙을 지우면 그 규칙으로 대기 중이던 자동회신 작업은 취소됩니다.
- **어느 규칙에도 맞지 않는 메일**: "무시"(기본) 또는 "초안 만들기" 중에서 고릅니다.
  창을 닫을 때 저장됩니다.

## 규칙 편집

- **이름**, **적용 계정**(모든 계정 또는 특정 계정), **이 규칙 사용**
- **조건**: [조건 추가]로 줄을 늘리고, 각 줄에서 항목·비교·값을 정합니다.
  - 결합 방식: **모두 만족(AND)** 또는 **하나라도 만족(OR)**
  - 항목: 보낸사람 주소, 보낸사람 도메인, 받는사람, 참조, 제목, 본문, 첨부 있음,
    받은 시각(시), 받은 요일(0=월 ~ 6=일)
  - 비교: 같음, 포함, 포함하지 않음, ~로 시작, ~로 끝남, 정규식(RE2),
    목록 중 하나(쉼표로 구분), 범위(시작-끝)
  - 대소문자는 구분하지 않습니다.
  - **범위**는 "시작 이상, 끝 미만"입니다. 예) 받은 시각 `9-18`은 09:00~17:59.
    시작이 끝보다 크면 자정을 넘깁니다. 예) `18-9`는 18:00~08:59.
  - 받은 시각·요일은 **이 PC의 시간대** 기준입니다.
  - **정규식은 RE2 문법**이고 200자 이하입니다. 역참조(`\1`)와 전후방탐색(`(?=…)`)은 쓸
    수 없습니다(저장할 때 오류로 알려 줍니다). 본문은 앞 10,000자만 검사합니다.
  - 조건이 하나도 없으면 받은 **모든 메일**에 맞습니다(저장할 때 경고합니다).
- **동작**
  - **무시(답장하지 않음)**
  - **초안 만들기(직접 검토 후 발송)**
  - **즉시발송 — 다음 업데이트에서 제공 예정**: 목록에는 보이지만 고를 수 없습니다
    (마우스를 올리면 이유가 보입니다). 예전에 즉시발송으로 저장된 규칙이 있다면 이번
    버전에서는 초안으로 동작하고, 편집해서 저장하면 "초안 만들기"로 바뀝니다.
- **응답 방식**
  - **Claude가 작성**: 앱이 claude CLI를 실행해 답장 본문을 쓰게 합니다. claude CLI를
    먼저 고정해 두어야 합니다([Claude/MCP 패널 > 잡 탭](05_Claude_MCP패널.md)).
  - **고정 템플릿**: Claude를 쓰지 않고 정해 둔 문장을 그대로 씁니다. 다음 자리표시자만
    쓸 수 있습니다: `{sender_name_safe}`(보낸사람 이름 — 링크·주소처럼 보이면 비움),
    `{received_date}`(받은 날짜), `{account_name}`(내 계정 이름).
- **추가 지침**(Claude 작성일 때, 1000자 이하), **최대 글자 수**(50~2000, 기본 400)

## 드라이런(미리 시험하기)

**[드라이런(최근 50건에 적용해 보기)]**을 누르면, 지금 편집 중인 규칙을 받은편지함의
최근 메일 50건에 적용해 보고 결과를 표로 보여 줍니다.

- **claude는 실행하지 않고**, 메일·초안도 만들지 않습니다. 자동회신이 꺼져 있어도 됩니다.
- 위쪽 요약: "최근 N건 중 규칙에 맞음 N건, LoopGuard 차단 N건, 초안 예정 N건"
- 결과 열: **초안 예정** / **무시** / **맞지 않음** / **차단(LoopGuard)** — 차단이면 사유가
  함께 표시됩니다.
- 표의 제목·보낸사람은 받은 메일 그대로이며, 서식 없이 글자로만 표시됩니다.

## 자동으로 건너뛰는 메일(LoopGuard, 끌 수 없음)

메일 폭주와 자동응답끼리 주고받는 루프를 막기 위해, 다음 메일은 규칙과 관계없이
**차단**됩니다(자동회신 로그에 사유가 남습니다).

- 자동응답·자동생성 표시가 있는 메일(`Auto-Submitted`, `X-Autoreply` 등), 대량·메일링
  리스트 메일(`Precedence: bulk`, `List-Id` 등)
- 반송·수신확인 메일, `noreply`/`mailer-daemon`/`postmaster` 같은 발신자
- 제목에 "Out of Office", "자동 응답", "부재중", "반송", "Undeliverable" 등이 있는 메일
- **내가 보낸 메일**(모든 내 계정 주소와 별칭 — 계정끼리 주고받는 루프 포함)
- 보낸사람이 여러 명이거나 `Sender`가 보낸사람과 다른 메일

또한 다음 메일은 **평가하지 않습니다**(아무것도 기록하지 않음): 받은편지함이 아닌
폴더(스팸 포함)의 메일, 자동회신을 켜기 전에 받은 메일, **폴더별 최초 동기화 때**
한꺼번에 받아 온 과거 메일(계정을 처음 추가했을 때 받은편지함에 이미 있던 메일 등),
보낸 날짜가 받은 시각보다 72시간 넘게 이전인 메일.

최초 동기화는 폴더마다 한 번뿐입니다. 그 뒤에는 받은편지함을 비우거나(메일을 보관함으로
옮기는 등) 메일을 지워도, 새로 들어오는 메일은 정상적으로 평가됩니다. 최초 동기화 중
일부 메일을 받지 못했더라도 최초 동기화는 그때 완료된 것으로 기록되므로, 그 뒤 새로 오는
메일은 바로 정상 평가됩니다. 받지 못했던 그 과거 메일은 프로그램을 끄기 전에 다시 받아 오면
과거 메일로 취급하고, 프로그램을 다시 시작한 뒤에 받아 오면 일반 메일처럼 평가됩니다(이 경우도
보낸 날짜가 72시간 넘게 지난 메일은 평가하지 않으며, 결과는 초안으로만 저장됩니다).

같은 메일(같은 Message-ID)을 다시 받아 온 경우에도 **다시 평가하지 않습니다** — 예를 들어
오프라인 상태에서 메일을 지워 이 PC에서만 휴지통으로 옮겨졌고, 서버 받은편지함에는 그대로
남아 다음 동기화 때 다시 내려온 경우입니다. 같은 계정에서 그 메일이 이미 한 번 평가됐거나
과거 메일로 빠졌다면, 다시 받은 사본으로는 자동회신 작업을 만들지 않습니다.

## 결과 확인

- 자동회신 작업(잡)의 진행 상황은 [Claude/MCP 패널 > 잡 탭](05_Claude_MCP패널.md)에서
  봅니다(대기 / 실행 중 / 완료 / 취소 / 실패와 사유).
- 만들어진 답장은 **초안**으로 저장됩니다. 받는사람은 원래 메일의 보낸사람 한 명이며,
  첨부는 붙지 않습니다. 직접 읽어 보고 고친 뒤 보내세요.
- 메일 목록의 **자동회신** 열에 메일별 처리 결과(무시·차단·대기·작성 중·초안·건너뜀·
  실패·취소)가 표시됩니다.
- 자동회신 작업에도 시간당 상한이 있습니다(같은 보낸사람 3건, 같은 도메인 10건, 전체 30건,
  대기 50건). 넘으면 그 메일은 "차단(job_cap)"으로 기록됩니다.
