# 설정

**도구 > 설정**에서 엽니다. 탭은 일반/업데이트/MCP/자동회신/프록시입니다.

## 일반 탭(이번 버전에서 실제로 동작합니다)

- **수신 주기(신규 계정 기본값)**: 새 계정을 만들 때 기본으로 들어가는 수신
  주기(분)입니다. 이미 만들어진 계정의 주기는 **도구 > 계정 > 편집**에서
  계정별로 따로 바꿉니다.
- **미리보기 위치**: "그리드 아래"(기본) 또는 "그리드 옆" 중에서 고릅니다.
  바로 적용됩니다.
- **테마**: "시스템 설정 따름"(기본, OS의 라이트/다크 모드를 따라갑니다),
  "라이트", "다크" 중에서 고릅니다. 선택하는 즉시 화면에 바로 적용됩니다.

## 업데이트 탭(이번 버전에서 실제로 동작합니다)

EmailToMCP는 GitHub에 게시된 **서명된 업데이트 정보**를 확인해서 새 버전이
있으면 알려 줍니다. 이번 버전은 **확인 + 알림 + 다운로드 페이지 링크**까지만
합니다. 앱 안에서 자동으로 내려받아 설치하는 기능은 이후 버전(U2)에서
제공됩니다 — 지금은 다운로드 페이지에서 설치 파일을 받아 직접 실행하세요.

- **현재 버전**: 지금 실행 중인 앱 버전입니다. 개발용 빌드(버전에 `.dev`나
  `+`가 붙은 경우)는 "(개발 빌드 — 자동 확인 기본 꺼짐)"으로 표시됩니다.
- **채널**: `stable`(안정판)만 제공합니다. 사전 릴리스(rc)는 안내하지 않습니다.
- **자동으로 업데이트 확인**: 켜 두면 앱을 시작하고 **30초 뒤**에 한 번, 그 뒤로는
  **24시간마다** 확인합니다. 기본값은 켜짐입니다(개발 빌드는 꺼짐). 바꾼 뒤
  **[저장]**을 눌러야 반영됩니다.
- **마지막 확인 / 확인 결과**: 가장 최근에 확인한 시각과 결과입니다.
  - "최신 버전입니다." — 할 일이 없습니다.
  - "새 버전 X.Y.Z이(가) 있습니다." — 메인 창 위쪽 배너에서 다운로드 페이지를 열 수
    있습니다. "(보안 업데이트)"가 붙어 있으면 가능한 한 빨리 설치하세요.
  - "필수 업데이트: …" — 지금 버전이 지원되는 최소 버전보다 낮습니다. 아래
    "필수 업데이트가 뜰 때"를 보세요.
  - "확인 불가: (사유)" — 인터넷 연결이 없거나, 서버의 업데이트 정보가 만료되었거나
    (서버 쪽 재서명 대기), 형식이 맞지 않아 받아들이지 않은 경우입니다. 앱 사용에는
    지장이 없고 다음 확인 때 다시 시도합니다. 자주 보이는 사유는 다음과 같습니다.
    - "이 빌드에는 업데이트 서명 검증 키가 내장되지 않아 확인할 수 없습니다" — 지금
      쓰는 빌드에 업데이트 정보를 검증할 키가 들어 있지 않아서, 안전을 위해 업데이트
      확인 자체를 하지 않습니다(인터넷 접속도 하지 않음). 새 버전 소식은 사내 위키 등
      별도 공지로 확인하고 직접 설치하세요.
    - "이 버전이 오래되어 새 서명키를 모릅니다 — 수동 업데이트가 필요합니다" — 개발자가
      서명키를 교체했는데 지금 버전은 새 키를 모르는 경우입니다. 보안 경보가 아니며,
      다운로드 페이지에서 최신 설치 파일을 받아 직접 설치하면 다시 자동으로 확인됩니다.
    - 회사 네트워크의 보안 장비가 업데이트 주소를 막아 다른 페이지를 돌려주는 경우에도
      "형식이 맞지 않음"으로 확인 불가가 표시될 수 있습니다(보안 경보는 뜨지 않습니다).
  - "보안 경보: …" — 아래 "보안 경보가 뜰 때"를 보세요.
- **[지금 확인]**: 바로 한 번 확인합니다. 메뉴 **도움말 > 업데이트 확인**도 같은
  동작입니다(결과를 작은 창으로 알려 줍니다).

### 어떻게 안전하게 확인하나요?

업데이트 정보는 개발자가 오프라인에서 만든 **전자서명**이 맞을 때만 믿습니다.
서명이 없거나 맞지 않거나, 예전 정보를 다시 내미는 경우(롤백), 지금보다 낮은
버전을 새 버전처럼 내미는 경우는 모두 무시합니다. 다운로드 페이지 링크도
`https://github.com/yuseungil-a11y/emailtomcp/releases/` 아래 주소만 엽니다.

### 필수 업데이트가 뜰 때(빨간 배너)

메인 창 위쪽에 **빨간 배너**("필수 업데이트: …")가 고정으로 뜨고 닫을 수
없습니다. 보안 문제 등으로 지금 버전을 더 이상 쓰지 않는 것이 좋다는 뜻입니다.

1. 배너의 **[다운로드 페이지 열기]**를 누릅니다(GitHub 릴리스 페이지가 브라우저로
   열립니다).
2. 운영체제에 맞는 설치 파일(Windows는 `EmailToMCP-win-Setup.exe`)을 받아 실행합니다.
3. 새 버전으로 앱을 다시 시작하면 배너가 사라집니다.

인터넷이 끊겨 확인이 실패하더라도, 한 번 확인된 필수 업데이트 배너는 계속
남아 있습니다.

### 보안 경보가 뜰 때

앱이 알고 있는 서명키로 서명된 업데이트 정보인데 서명이 맞지 않거나(내용이
바뀐 경우), 이미 받은 버전과 같은 버전인데 파일
지문(해시)이 다르면 **"업데이트 보안 경보"** 창이 한 번 뜨고, 상태줄에
`업데이트 ●보안 경보`가 표시되며 **자동 확인이 정지**됩니다. 이 때 앱은 아무
파일도 내려받거나 설치하지 않습니다.

- 누군가 업데이트를 위조했을 가능성이 있으니, 사내 위키 등 별도 채널의 공지를
  먼저 확인하세요.
- 문제가 해결되었다는 공지를 확인한 뒤 **[지금 확인]**을 누르면 다시 확인하고,
  정상으로 확인되면 자동 확인도 다시 시작됩니다.

### 7일 넘게 확인하지 못했을 때

자동 확인이 7일 넘게 계속 실패하면 메인 창 위쪽에 안내 배너가 뜹니다.
이 탭의 "확인 결과"에서 사유를 보고, 인터넷 연결이나 프록시 설정을 확인하세요.
배너의 [나중에]를 누르면 앱을 다시 시작할 때까지 숨겨집니다.

## MCP 탭(이번 버전에서 실제로 동작합니다)

Claude(MCP)를 통한 발송 정책과 MCP 서버 포트를 정합니다. 연결 방법과 토큰은
[Claude/MCP 패널](05_Claude_MCP패널.md)에서 다룹니다.

- **발송 모드**
  - **확인(기본)**: Claude가 발송을 요청할 때마다 [발송 승인 창](06_발송승인.md)이
    뜨고, 승인해야 발송됩니다.
  - **허용 목록**: 받는사람·참조·숨은참조 **모두**가 아래 허용 목록에 있을 때만 승인
    없이 바로 보냅니다. 한 명이라도 목록에 없으면 승인 창이 뜹니다. **첨부가 하나라도
    있으면(회신·전달·새 메일 모두) 항상 승인 창**이 뜹니다.
  - **사용 안 함**: Claude는 초안만 만들 수 있고, 발송 요청은 거부됩니다.
- **허용 목록**: 한 줄에 하나씩 주소(`boss@example.com`) 또는 도메인(`example.com`)을
  적습니다. 도메인은 정확히 같아야 하며 하위 도메인(`mail.example.com`)은 포함되지
  않습니다.
- **포트**: MCP 서버가 쓰는 `127.0.0.1`의 포트입니다(기본 8765). **앱을 다시 시작하면**
  적용됩니다. 다른 프로그램이 쓰고 있는 포트면 자동으로 다른 포트로 바꾸지 않고 MCP를
  끈 채 상태줄에 경고합니다. stdio 프록시로 연결했다면 Claude 쪽은 다시 등록하지 않아도
  됩니다.
- 발송 모드와 관계없이 Claude를 통한 발송은 **시간당 20건, 하루 100건**을 넘을 수
  없습니다.

## 자동회신 탭

탭 맨 위에 **[자동회신 사용]** 체크박스와 현재 상태가 있습니다.

- **기본은 꺼짐**입니다. 자동으로 메일을 보낼 수 있는 기능이라 처음에는 꺼져 있습니다.
- 상태 줄 예시: `상태: ○ 꺼짐 — 규칙 3개 보존됨 (마지막 변경 2026-10-05 14:02)`.
  켜져 있으면 `상태: ● 켜짐 — 규칙 3개 적용 중`으로 바뀝니다.
- 체크박스는 다른 설정과 마찬가지로 **[저장]을 눌러야 적용**됩니다.

**켜기(꺼짐 → 켜짐)**

1. [자동회신 사용]에 체크하고 [저장]을 누릅니다.
2. **확인 창**이 뜹니다. 창이 뜬 뒤 **1.5초 동안은 버튼이 눌리지 않습니다**(다른 창에서
   치던 Enter로 실수로 켜지지 않게 하기 위함입니다). 기본 버튼은 **[취소]**입니다.
3. 확인 창에는 사전점검 결과가 나옵니다 — 자동회신을 쓰는 계정 수, 활성 규칙 수(그중
   즉시발송 규칙 수), 인증 설정이 없어 즉시발송이 초안으로 바뀌는 계정 수 등입니다.
   참고용이며 켜기를 막지는 않습니다.
4. **[켜기]**를 누르면 켜집니다. [취소]를 누르면 켜지지 않고 설정 창이 그대로 열려 있습니다.

- **켠 이후에 받은 메일에만 적용됩니다.** 꺼져 있는 동안 받은 메일은 다시 켜도 자동회신
  대상이 되지 않습니다(소급 적용 없음).
- 설정 창을 연 뒤 다른 곳에서 상태가 바뀌었다면 "다른 곳에서 바뀌었습니다. 다시
  확인하세요" 경고가 뜨고 최신 상태를 다시 읽어 옵니다. 내용을 확인한 뒤 다시 [저장]하세요.

**끄기(켜짐 → 꺼짐)**

- 체크를 풀고 [저장]을 누르면 **확인 창 없이 바로** 꺼집니다(멈추는 쪽은 안전하기 때문).
- 결과 창에 "실행 중이던 잡 n건 취소, 발송 대기 n건을 초안으로 되돌림, 이미 전송 중이던
  n건은 취소할 수 없음"이 표시됩니다. 초안으로 되돌아간 메일은 직접 검토한 뒤 보낼 수
  있습니다.
- 꺼도 **규칙과 계정별 자동회신 설정은 지워지지 않습니다.** 다시 켜면 그대로 적용됩니다.
- 꺼져 있으면 자동회신 규칙은 전혀 평가되지 않습니다. 대화형 Claude(MCP) 연결은 이
  설정과 관계없이 그대로 동작합니다.

> 현재 버전 안내: 자동회신 규칙은 [도구 > 규칙 설정](04_규칙설정.md)에서 만듭니다. 이번
> 버전의 자동회신은 답장을 **초안으로만** 만들고(직접 검토 후 발송), 사람 확인 없이 보내는
> 즉시발송은 다음 업데이트에서 제공됩니다. 사전점검의 "claude CLI 고정" 항목은
> [Claude/MCP 패널 > 잡 탭](05_Claude_MCP패널.md)에서 고정했는지를 보여 줍니다(미고정이면
> 고정 템플릿 규칙만 동작합니다).

탭 아래쪽의 **자동회신 타임아웃(초)**은 꺼져 있어도 편집할 수 있습니다.

메인 창 상태줄의 `자동회신 ○꺼짐`/`자동회신 ●켜짐`을 클릭해도 이 탭이 바로 열립니다
([01_메인창.md](01_메인창.md)).

## 프록시 탭

`HTTPS_PROXY` 주소 입력란만 있습니다. **claude 자식 프로세스에 프록시를 넘기는
실제 동작은 U2(자동 업데이트 안정화 이후)에서 제공됩니다** — 지금은 설정값만
저장됩니다.

## 저장 위치

여기서 바꾸는 값은 모두 앱 데이터베이스의 설정 테이블에 저장됩니다(계정별
설정과는 별도입니다). 비밀번호 등 민감한 값은 이 화면에서 다루지 않습니다
(계정 비밀번호는 `도구 > 계정`에서, OS 키체인에만 저장됩니다).
