# Claude/MCP 패널

**Claude > Claude/MCP 패널**에서 엽니다. Claude Code(또는 Claude Desktop)가 이 앱의
메일을 읽고, 초안을 만들고, 발송을 **요청**할 수 있게 연결하는 화면입니다.

> **발송은 항상 사용자가 결정합니다.** Claude는 초안을 만들고 발송을 요청할 수만
> 있고, 기본 설정에서는 이 앱에 뜨는 **발송 승인 창**에서 사용자가 [승인]해야
> 실제로 발송됩니다. 승인 창 사용법은 [06_발송승인.md](06_발송승인.md)를 보세요.

> 이 화면에서 설명하는 기능(대화형 메일검색·초안생성·발송·회신)은 **Claude
> Desktop만으로 충분**하며 별도 CLI 설치가 필요 없습니다. [자동회신(규칙 기반
> 자동답장)](04_규칙설정.md) 기능을 쓰실 때만 claude CLI 설치가 필요합니다 —
> 자세한 내용은 [04_규칙설정.md](04_규칙설정.md)의 "이 기능을 쓰려면(claude CLI
> 필요)"를 참고하세요.

## 동작 원리(요약)

- 앱이 실행되는 동안 내 PC 안에서만 접근할 수 있는 MCP 서버(`127.0.0.1`, 기본 포트
  `8765`)가 켜집니다. 다른 PC나 웹 브라우저에서는 접근할 수 없습니다.
- Claude는 **stdio 프록시**(이 앱 실행파일을 `--mcp-stdio-proxy` 옵션으로 실행한 것)를
  통해 연결합니다. 프록시는 실행 중인 앱에 먼저 "진짜 EmailToMCP 앱인지" 확인
  (공유 비밀 기반 핸드셰이크)한 뒤, OS 키체인에 저장된 토큰으로만 요청을 전달합니다.
  그래서 **토큰이 Claude 설정 파일, 명령줄, 셸 기록, 클립보드에 남지 않습니다.**
- **앱이 꺼져 있으면** Claude 쪽에 "EmailToMCP 앱을 실행하세요"라는 오류가 납니다.
  앱을 켜면 Claude를 다시 등록하지 않아도 바로 연결됩니다.

## 처음 연결하기(stdio 프록시, 권장)

1. **토큰 탭 > [발급]**을 누릅니다.
   - 연결 방식: **stdio 프록시(권장)**
   - 프록시 프로필: `default`(그대로 두세요)
   - 권한: 기본값(**읽기 + 초안 작성**)으로 시작하는 것을 권장합니다. Claude에게
     발송까지 요청하게 하려면 **발송 요청**을, 읽음 표시·플래그·휴지통 이동까지
     맡기려면 **메일 관리**를 추가로 체크하세요.
   - [확인]을 누르면 토큰이 OS 키체인에 저장되고(화면에는 표시되지 않습니다),
     바로 이어서 **"Claude 연결 안내"** 팝업이 뜹니다.
2. 팝업에 뜬 등록 명령을 **[복사]**해서 터미널에서 한 번 실행합니다. 예)

   ```
   claude mcp add emailtomcp --scope user -- "C:\...\EmailToMCP.exe" --mcp-stdio-proxy
   ```

   이 명령에는 토큰이 들어 있지 않으므로(토큰은 OS 키체인에만 저장됩니다) 그대로
   복사해도, **[파일로 저장]**으로 `.txt` 파일에 남겨 둬도 안전합니다. 같은 팝업에
   Claude Desktop용 설정 JSON 조각(`command`/`args`)도 같이 보여 줍니다.
   팝업을 닫은 뒤 다시 보고 싶으면 **서버 탭 > [연결안내 다시보기]**를 누르세요.
3. Claude Code를 다시 시작하고 "내 메일 계정 목록 보여줘"처럼 요청해 보세요.
   연결되면 메인 창 상태줄의 **Claude ●연결됨**이 켜집니다.

- **Claude Desktop**은 팝업에 나온 JSON 조각(`command`에 실행파일 경로, `args`에
  `["--mcp-stdio-proxy"]`)을 설정 파일에 그대로 추가하면 같은 방식으로 연결됩니다.
- 프로필을 여러 개 쓰려면(예: 업무용/개인용 Claude) 토큰을 다른 프로필 이름으로
  발급하세요. `default`가 아닌 프로필로 발급하면 팝업의 등록 명령과 Claude Desktop용
  JSON에 `--client <프로필>`이 자동으로 붙으므로 따로 덧붙일 필요가 없습니다.

### VSCode(Claude Code 확장)에서 연결하기

VSCode의 **Claude Code** 확장은 내부적으로 Claude Code CLI를 그대로 사용하므로,
독립 실행형 CLI와 **동일한 등록 명령**을 그대로 쓰면 됩니다. 확장 전용 그래픽
설정 화면은 따로 없습니다.

1. VSCode에 **Claude Code** 확장이 설치돼 있어야 합니다.
2. 위 1번 **토큰 탭 > [발급]**으로 발급할 때 뜨는 **"Claude 연결 안내"** 팝업(또는
   **서버 탭 > [연결안내 다시보기]**)에서 등록 명령을 **[복사]**합니다.
3. VSCode에서 **터미널 > 새 터미널**(통합 터미널)을 열고, 복사한 명령을 그대로
   붙여넣어 실행합니다. 독립 실행형 CLI에서 쓰는 것과 **완전히 같은 명령**입니다
   (VSCode 확장이 같은 CLI 설정을 공유하기 때문입니다).
4. 등록이 끝나면 VSCode의 Claude Code 패널(또는 채팅창)을 다시 시작하거나 새
   대화를 시작하면 연결됩니다.
5. 등록 명령은 기본적으로 `--scope user`로 등록합니다(그 PC의 모든
   프로젝트/워크스페이스에서 공통으로 쓰입니다). 특정 프로젝트에서만 쓰려면 명령의
   `--scope user`를 `--scope project` 또는 `--scope local`로 바꿔서 실행하세요.
6. 여러 Claude Desktop/VSCode/CLI를 동시에 쓰면서 프로필을 구분하고 싶다면, 위
   "프로필을 여러 개 쓰려면" 안내(`--client <프로필>`)가 VSCode 쪽에도 똑같이
   적용됩니다.

## HTTP 직결(고급)

stdio 프록시 대신 URL(`http://127.0.0.1:<포트>/mcp`)로 직접 연결할 수도 있습니다.

- 토큰 탭에서 연결 방식 **HTTP 직결(고급)**로 발급합니다. 토큰은 **발급할 때 한 번만**
  (가려진 상태로) 표시됩니다. [표시]로 확인하고 [복사]하면 클립보드 기록에서 제외되는
  형식으로 복사되며 **60초 뒤 클립보드에서 자동으로 지워집니다.**
- 토큰을 셸 명령(`claude mcp add ... --header ...`)으로 등록하지 마세요. 셸 기록과
  설정 파일에 평문으로 남습니다. 대신 토큰을 사용자 환경변수(예: `EMAILTOMCP_TOKEN`)에
  두고, Claude 설정 파일을 **직접 편집**해 헤더 값을 `Bearer ${EMAILTOMCP_TOKEN}`처럼
  환경변수 참조로 넣으세요.
- HTTP 직결은 앱 포트를 바꾸면 설정을 직접 고쳐야 합니다(stdio 프록시는 자동으로
  따라갑니다).

## 서버 탭

- **MCP 서버**: `●실행 중 — 127.0.0.1:8765`처럼 표시됩니다.
- **포트 충돌**: 다른 프로그램이 같은 포트를 쓰고 있으면 MCP 서버는 **꺼진 상태로
  남고** 경고가 표시됩니다(보안상 다른 포트로 자동으로 바꾸지 않습니다).
  **도구 > 설정 > MCP 탭**에서 포트를 바꾸고 앱을 다시 시작하세요. stdio 프록시로
  연결했다면 Claude 쪽은 다시 등록할 필요가 없습니다.
- **Claude 연결**: Claude가 요청을 보내면 `●연결됨`, 마지막 요청 후 5분 동안 요청이
  없으면 `●미연결`로 바뀝니다.
- **[연결안내 다시보기]**: 토큰 발급 직후에 뜨는 "Claude 연결 안내" 팝업(등록 명령
  복사/파일저장, Claude Desktop용 JSON)을 언제든 다시 엽니다.
- 자동회신에 쓰는 claude CLI의 경로 고정은 **잡 탭**에서 합니다. claude 버전·인증 방식
  표시와 [테스트] 버튼은 다음 업데이트에서 제공됩니다.

## 토큰 탭

| 열 | 뜻 |
|---|---|
| 라벨/프로필 | 프록시 토큰은 프로필 이름, HTTP 토큰은 붙인 라벨 |
| 종류 | 프록시 / HTTP |
| 스코프 | 읽기 · 초안 · 발송 · 관리 중 허용된 권한 |
| 마지막 사용 | 이 토큰으로 마지막 요청이 온 시각 |
| 만료 | 기본 180일 |
| 상태 | 유효 / 폐기됨 |

- **[폐기]**: 선택한 토큰을 즉시 무효화합니다. 그 토큰을 쓰던 Claude 연결은 다음
  요청부터 거부됩니다. 같은 프로필로 프록시 토큰을 새로 발급하면 이전 토큰은 자동으로
  폐기됩니다.
- 권한별로 Claude가 쓸 수 있는 도구:

| 권한 | 도구 |
|---|---|
| 읽기 | 계정·폴더·메일 목록, 검색, 메일/스레드 읽기, 초안 목록·상태, 즉시 수신 |
| 초안 작성 | 새 메일·회신·전달 초안 만들기, 초안 수정·삭제(작성 중 상태이고 **그 연결로 Claude가 만든 초안만**) |
| 발송 요청 | 초안 발송 요청(기본: 앱에서 승인해야 발송, **그 연결로 Claude가 만든 초안만**) |
| 메일 관리 | 읽음/안읽음, 플래그, 휴지통으로 이동(영구 삭제 없음) |

  권한이 없는 도구는 Claude에게 보이지도 않고, 직접 호출해도 거부됩니다.
- **내가 직접 쓰던 초안은 Claude가 고치거나 지우거나 발송 요청할 수 없습니다.** Claude는
  초안 목록을 볼 수는 있지만, 수정·삭제·발송 요청은 **같은 연결(토큰)로 Claude가 만든
  초안**에만 할 수 있습니다. 토큰을 다시 발급하면 이전 토큰으로 만든 초안은 앱에서 직접
  처리하세요.

## 잡 탭(자동회신 작업)

[규칙 설정](04_규칙설정.md)에 따라 자동회신 답장 초안을 만드는 작업(잡)을 보여 줍니다.

- **자동회신이 꺼져 있으면** 맨 위에 "자동회신이 꺼져 있습니다" 안내가 보이고
  [일시정지]/[재개] 버튼이 비활성화됩니다.
- **큐 상태**: `실행 중` / `일시정지(사용자)` 등과 대기·실행 중·완료·취소·실패 건수.
  - **[일시정지]**: 새 작업을 시작하지 않습니다(대기 중인 작업은 그대로 남습니다).
  - **[재개]**: 다시 시작합니다.
- **자동발송**: 이번 버전에서는 제공하지 않습니다 — 자동회신 결과는 모두 **초안**입니다.
- **claude CLI**: "Claude가 작성" 규칙에 쓸 claude 실행 파일 상태입니다.
  - `미고정`이면 Claude 작성 규칙은 실행되지 않고(작업이 "실패: claude CLI 미고정"으로
    끝남), 고정 템플릿 규칙만 동작합니다.
  - **[claude CLI 찾기·고정]**: 이 PC에서 찾은 후보 경로를 보여 줍니다(이 단계에서는
    claude를 실행하지 않습니다). 하나를 고르거나 직접 경로를 입력해 고정하면, 경로와 파일
    지문(sha256)이 저장되고 실행할 때마다 지문을 다시 확인합니다. claude가 업데이트되어
    파일이 바뀌면 `확인 필요`로 표시되며 다시 고정해야 합니다.
  - npm으로 설치한 경우 `claude.cmd` 대신 `node.exe`와 `cli.js`로 고정됩니다(명령
    프롬프트를 거치지 않기 위해서입니다). 임시 폴더·다운로드 폴더 안의 파일은 고정할 수
    없습니다.
- **잡 목록**: ID, 만든 시각, 보낸사람, 제목, 규칙, 상태(대기·실행 중·완료·취소·실패),
  결과(초안 생성·건너뜀(Claude 판단)·폐기), 사유가 보입니다. 제목·보낸사람은 받은 메일에서
  온 값이라 서식 없이 글자로만 표시합니다.
- **[초안 열기]**: 결과가 "초안 생성"인 줄을 고르고 누르면(또는 줄을 더블클릭) 그 초안을
  **작성 창**으로 엽니다. 내용을 확인·수정한 뒤 직접 보내세요. 이미 보냈거나 삭제한 초안은
  열 수 없다는 안내가 나옵니다.
  - 작성 창 맨 위에는 초안을 만든 방식이 표시됩니다: Claude가 작성한 자동회신 초안은
    "자동회신 초안(Claude 작성)", 고정 템플릿 규칙으로 만든 초안은 "자동회신 초안(고정 템플릿)".
  - 초안에 **링크(URL), 이메일 주소, 전화번호, 계좌번호로 보이는 숫자, 금액, 확정·약속 표현,
    인용 줄, 받은 메일 원문을 그대로 옮긴 부분** 등이 있으면 작성 창 위쪽에 **주의 배너**가
    보입니다. 받은 메일에 숨어 있던 지시가 답장에 섞였을 수 있으니, 해당 내용을 직접 확인한
    뒤 보내세요(배너는 초안이 처음 만들어졌을 때의 점검 결과입니다).

자주 보이는 사유:

| 사유 | 뜻 |
|---|---|
| 즉시발송 미지원 → 초안 | 즉시발송 규칙이지만 이번 버전이라 초안으로 만들었습니다 |
| claude 사용자 설정(hooks·플러그인 등) 감지로 실행 안 함 | 아래 "안전장치" 참고 |
| claude CLI 미고정·변경됨 | 잡 탭에서 claude CLI를 (다시) 고정하세요 |
| MCP 서버 꺼짐 | MCP 서버가 켜져야 Claude 작성 작업이 진행됩니다 |
| 허용 외 도구 사용(보안 폐기) | claude가 허용되지 않은 도구를 썼습니다(시간 초과로 멈춘 경우 포함). 결과를 버렸습니다 |
| 제출 2회 이상(보안 폐기) | claude가 결과를 두 번 이상 제출하려 했습니다. 결과를 버렸습니다 |
| 사후 검증 재확인: …(보안 폐기) | 결과를 초안으로 확정하기 직전에 사용 도구·제출 횟수·종료 코드·제출 기록을 한 번 더 확인했는데 어긋났습니다. 결과를 버렸습니다 |
| 실행 중 claude 설정 변경 감지(보안 폐기) | 작업 도중 claude 사용자 설정·`CLAUDE.md`·관리 정책 파일이 바뀌었습니다. 결과를 버렸습니다 |
| 잡 폴더에 예상 밖 파일 생성(보안 폐기) | 빈 작업 폴더에 파일이 생겼습니다. 결과를 버렸습니다 |
| 잡 폴더 상위에 claude 설정 발견 / 잡 폴더 권한 설정 실패 | 작업 폴더 환경이 안전하지 않아 초안을 만들지 않았습니다 |
| 규칙 변경·중지·삭제 / 계정 자동회신 꺼짐 | 작업 중에 설정이 바뀌어 초안을 만들지 않았습니다 |

### 자동회신 작업의 안전장치

- claude는 **빈 작업 폴더**에서, 내장 도구(파일·셸 등) 없이, 이 앱이 정한 **두 도구**
  (메일 1건 읽기, 결과 1회 제출)만 쓸 수 있게 실행됩니다. 받는 사람과 발송 여부는 claude가
  아니라 앱이 정합니다.
- 작업마다 그 작업에만 쓸 수 있는 임시 토큰이 발급되고, 끝나면 바로 폐기됩니다. 이 토큰으로는
  위 두 도구 외의 메일 읽기·초안·발송 도구를 쓸 수 없고, 반대로 Claude Code 연결용
  토큰으로는 이 두 도구를 쓸 수 없습니다.
- **claude 사용자 설정**(`~/.claude/settings.json`, `settings.local.json`)과 관리자 정책
  파일(`C:\Program Files\ClaudeCode\managed-settings.json` 등)은 **안전하다고 확인된 항목만
  허용**합니다. 그 밖의 항목(예: hooks, 활성 플러그인, MCP 외 도구 허용 규칙, 권한 우회 모드,
  모델·출력 스타일·상태줄 명령 같은 설정, 비어 있지 않은 `env` 블록)이 하나라도 있거나 파일을
  읽을 수 없으면, 그 설정이 자동회신 작업에 섞일 수 있어 **claude를 실행하지 않고 작업을
  취소**합니다(사유: "claude 사용자 설정(hooks·플러그인 등) 감지로 실행 안 함").
  자동회신을 쓰려면 해당 설정을 정리하거나 고정 템플릿 규칙을 쓰세요.
- 환경변수 `CLAUDE_CONFIG_DIR`로 claude 설정 폴더를 옮겨 쓰는 PC도 같은 이유로 지원하지
  않습니다(Claude 작성 작업이 같은 사유로 취소됩니다).
- 작업이 끝나면 claude가 실제로 쓴 도구 목록·제출 횟수·종료 코드와, 작업 중에 claude 설정·
  `~/.claude/CLAUDE.md`가 바뀌지 않았는지, 작업 폴더에 예상 밖 파일이 생기지 않았는지를
  확인하고, 하나라도 어긋나면 결과를 버립니다.
- 작업 도중 그 규칙을 지우거나 끄거나 고치면, 또는 계정의 자동회신을 끄면 진행 중인 작업이
  바로 취소되고 claude 실행도 중단됩니다. 중단 직전까지 claude가 허용 외 도구를 쓰려 했거나
  결과를 두 번 이상 제출하려 했다면, 취소와 별개로 자동발송을 **보안 정지**합니다.
- 환경변수에 사용자 홈 폴더(Windows는 `USERPROFILE`)가 없으면 claude가 실제로 읽을 설정
  폴더를 정확히 알 수 없어, Claude 작성 작업을 실행하지 않고 취소합니다(사유: "claude 사용자
  설정(hooks·플러그인 등) 감지로 실행 안 함").

## 감사 로그 탭

Claude의 모든 요청(성공·거부·오류)이 기록됩니다. 자동회신 작업의 요청은 주체가
"잡"으로 표시됩니다. 시각, 토큰(번호와 해시 앞 8자리),
도구, 결과, 상세가 보입니다. **메일 본문·제목 같은 내용은 기록하지 않고 길이와 해시만
남깁니다.** 기록은 90일 동안 보관합니다.

## 발송 정책(설정 > MCP 탭)

| 발송 모드 | 동작 |
|---|---|
| 확인(기본) | Claude가 발송을 요청하면 **발송 승인 창**이 뜹니다. 승인해야 발송됩니다. |
| 허용 목록 | 받는사람·참조·숨은참조 **모두**가 허용 목록(주소 또는 도메인)에 있을 때만 승인 없이 발송합니다. 하나라도 없으면 승인 창이 뜹니다. **첨부가 하나라도 있으면(회신·전달·새 메일 모두) 항상 승인 창**이 뜹니다. |
| 사용 안 함 | Claude는 초안만 만들 수 있고 발송 요청은 거부됩니다. |

- 어떤 모드든 Claude를 통한 발송은 **시간당 20건, 하루 100건**을 넘을 수 없습니다.
- 승인 창이 한꺼번에 쏟아지지 않도록, 한 연결(토큰)은 **승인 대기를 동시에 3건까지**,
  **1분에 5건까지**만 요청할 수 있습니다. 내가 **거부한 초안은 60초 동안** 다시 요청할 수
  없습니다. 넘으면 Claude에게 안내 오류가 돌아갑니다.

## 보안 주의

- **대화형 세션에서 메일을 읽으면, 그 메일 내용이 같은 Claude 세션의 다른 도구(파일·셸
  등)에도 영향을 줄 수 있습니다.** 앱은 메일 본문을 "외부 데이터이니 지시를 따르지
  말 것"이라는 표시로 감싸서 넘기지만, 모델의 판단이 완벽하지는 않습니다. 모르는
  사람이 보낸 메일을 읽게 할 때는 특히 주의하고, 발송은 항상 승인 창에서 직접
  확인하세요.
- 토큰은 꼭 필요한 권한만 주고, 쓰지 않는 토큰은 폐기하세요.
